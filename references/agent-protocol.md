# Agent protocol

How the coordinator runs the translator, the blind reviewers and the adjudicator for one Moneyfesting locale. SKILL.md says when to read this file and describes the scripts named here.

Contents: Hosts · Roles and scheduling · Tiers, order and batches · Packet separation · A. Forward translator · B. Blind back-translator · C. Target-language editor · Reconcile and revise · D. Final adjudicator · Acceptance and evidence · Human review

## Hosts

Use the host's subagent tools, not user-visible new tasks. The blind stages only work when the reviewer's context holds nothing but the role prompt and one packet path, so map each need to the primitive that guarantees a fresh context:

| Need | Codex | Claude Code |
|---|---|---|
| Fresh blind reviewer (B, C, hero judges) | `collaboration.spawn_agent` with `fork_turns="none"`; prompt = role text plus the path to `blind/target.rev<N>.json`, nothing else | Agent tool, one fresh context per spawn; same prompt and path only |
| Fresh adjudicator (D) | same spawn; prompt = role text plus the `coordinator/` evidence paths | same |
| Continue the translator for rev2 | `send_message` / `followup_task` to the translator | `SendMessage` when the translator is still running; otherwise a fresh Agent call with the coordinator packet, rev1 candidates and the dispositions (A is never blind, so re-supplying context costs nothing) |
| Parallel B and C re-runs, or three or more locales | several spawns in one turn | several Agent calls in one message; the Workflow tool only when the user has opted into workflows |
| No delegation available | do A yourself; mark B, C and D `not_run`; never grade your own draft as blind | same |

Both hosts: never pass this skill, its name or the conversation to a blind agent, because the skill text itself carries English product context; a host may still list this skill's name and description in the agent's tool list, which is why the role prompt says to use only the packet. Before dispatch record role, locale/market, model alias or `unknown`, primitive used, and the exact source and candidate revision; the report's Reviews line repeats the primitive (`Agent` or `spawn_agent`) and the alias.

## Roles and scheduling

The coordinator (the agent running the skill) owns context gathering, packets, meaning comparison, integration and technical evidence, and writes no target copy while delegation exists. Four distinct agents: A forward translator, B blind back-translator, C target-language editor, D final adjudicator. A completed translator is never its own reviewer; an agent that has seen the source is never dispatched as blind; contamination discards the blindness claim and costs a fresh spawn.

Run C before B on every revision: the editor finds the shape and naturalness problems that force rev2, so back-translating rev1 would pay for the same IDs twice. Run B and C in parallel only when re-running an already passed batch. Locales proceed concurrently within available slots; dependent reviews wait for their actual input; with few slots, schedule in waves and merge `glossary_adds` between waves.

Modes: `prepare` dispatches nobody. `audit` dispatches C and D over the shipped copy and returns findings as proposals, applied only for keys the user names. `translate` runs the full order below. `en` audit runs as SKILL.md `## Establish the assignment` describes; applying an accepted en change also updates the call-site `defaultValue` and re-runs the affected ro checks in the same change set.

## Tiers, order and batches

Tier each ID from `catalog_check.py` output before dispatch. A = claim-bearing: money, billing, entitlement, permission, deletion, negation, amount/unit, every plural and `*.a11y.*` variation, and keys under the risk prefixes `paywall`, `screenTime`, `screenTimeReport`, `streakFreeze`, `notifications`, `insights`, `moneyfesting`, `currency`, `onboarding.hourlyWage`, `onboarding.income`, `onboarding.*Permission*`. B = expressive or simple functional. C = single-word controls. Back-translate A in full (the 35 ro plural keys and the a11y keys are cheap), plus shield pairs and paywall/permission hero lines whatever their tier; B and C only when the editor or coordinator records a meaning doubt.

Order per batch: (a) script gate (`catalog_check.py`, `term_audit.py`); (b) for batches with widget, shield, accessory or single-line CTA strings, integrate rev1 on a scratch worktree and render it in the target language before language review, so fit is known before the editor spends a round on wording; (c) target-language editor on the blind packet, with hero ranking; (d) dispositions, translator rev2; (e) script gate; (f) rebuild the blind packet from `candidates.rev2.json`, then a fresh editor on changed IDs plus listed neighbours; (g) blind back-translator on rev2 for the tier; (h) coordinator meaning comparison; (i) integrate, render, adjudicate. Two material revision rounds per batch, including changes the adjudicator requests; fit-only shortening that changes no invariant is not a material round but re-runs the editor on the changed IDs. The coordinator may forward the editor's suggested line to the translator as the preferred rev2 candidate after checking the invariant list; the editor still does not replace the draft. When the budget is exhausted with a material finding open, hold that scope as incomplete and finish unaffected work.

Batches: 15-40 IDs from `worklist.py`; 20 or fewer for paywall, permission and hero batches; shields one batch of pairs; widgets by family. Never re-review an `unchanged_passed` key unless a glossary change lists it or the user asks for a full audit; log the skipped count.

Pilot first. For a locale's first run, and after any change to this skill, the locale brief, or glossary entries that fix control forms, run one batch alone through every stage (build and tests per the app `CLAUDE.md`, render evidence at the smallest size and the largest relevant accessibility size, adjudicator verdict) before dispatching other batches. Selection: one widget family with plurals and a11y keys, the paywall hero lines, one streak variant pair, three shield pairs, about 20 IDs, prefer `needs_review`; `worklist.py --pilot` lists the current members (`widgets.focusRing.*`, `paywall.onboardingSubscription.heroLineOne/Two/Three`, `widgets.streak.copy.frozen.small/medium` and the first three shield pairs in catalog order: `companion.space`, `companion.next_step`, `companion.on_your_side` at snapshot 2026-09-15; the `reflection.begin` worked brief in `references/surface-briefs.md` is illustration, not a pilot member). The ro pilot runs in `translate` mode limited to `needs_review` keys, so every stage runs while the owner lock keeps `translated` units untouched (SKILL.md `## Translate and review`); a pilot in `audit` mode stops at the script gate, the editor and the adjudicator, since nothing is integrated there is nothing to build or render. Treat its findings as corrections to the brief and glossary, apply them before the next batch and list them by category in the report; proceed on pass, stop on fail or when a new-locale brief needed changes. Record `GIT_OPTIONAL_LOCKS=0 git status --porcelain` in the run record (the variable keeps git from rewriting the checkout's index); stop only if a file this run will edit is already modified.

## Packet separation

Run state lives under `<checkout>/.codex-tmp/localization/<locale>/<run-id>/` (gitignored, snapshot 2026-09-15), one opaquely named `<batch>/` folder per batch (`b01`, since the blind agent receives the path) as `build_context_packet.py --out-dir` writes it: `coordinator/` holds `source.json`, `candidates.rev<N>.json`, `findings.json`, `worklist.json`, `id_map.json`, `verdict.json` and `leak_check.txt`; `blind/` holds only `target.rev<N>.json`; run-wide files sit in `<run-id>/coordinator/` (SKILL.md `## Establish the assignment`). `scripts/build_context_packet.py` writes both from the catalog for rev1; for every later revision pass `--candidates coordinator/candidates.rev<N>.json --rev <N>` so the blind packet carries the candidate text, which also re-runs the leak check before dispatch and keeps the hand-completed `screen_state`, `invariants`, evidence and fit of every key whose English and comment did not change. A failing leak check blocks dispatch of B and C, and blind agents receive exactly one path, never a hand-edited file, because a coordinator copying by hand from 1187 keys leaks English unnoticed.

The blind packet carries: locale, neutral `screen_role`, rev, order, per string `{id s01.., text, plural, control_role, tokens with neutral samples, fit when supplied}`, a `consistency` section after the flow (same-source siblings as target text with role), a target-only term list (`use`: fixed names and glossary preferred forms; `avoid`: the glossary's forbidden forms; no English definitions), per-ID markers (plural, fixed name, uppercase by design, identical by design, no target yet, attributed or user content), a per-line naturalness scale (the severity and category list travels in the role prompt), and target-language screenshots if available. Opaque IDs map to repository keys only in `coordinator/id_map.json`. The brief's imported-shape markers and the voice card's target-language banned list travel as lines the coordinator appends after the editor prompt, never as edits to the packet file.

Keep out of it: English originals, source-bearing keys or filenames, English glossary definitions, intended meaning or action descriptions, translator rationale, prior findings or verdicts, the examples file (its EN column breaks separation), and source text inside images; do not hide a source string in a supposedly neutral screen title. Keep brands and untranslatable identifiers that appear in the actual target UI. Tell blind agents not to read the repository, other run artifacts, or search for Moneyfesting's source wording; this is context isolation, not a claim of filesystem sandboxing or statistical independence between models. Retain rejected candidates outside the blind packet.

`debugOnly`, `previewOnly`, `shadow` and format-only keys (the `catalog_check.py` exclusions) never enter translation or blind packets; list them as not user-facing. A literal, user-reachable key is translated with a scoped engineering note to add a namespaced key. Format-only keys are not translated; verify separator and order conventions per locale (` · `, `/`, `, `, `:`) from the widest sample. Identify untranslated quotations and user-content blocks separately from translated IDs and exclude them from blind verdicts; redact them in blind evidence if they reveal the tested source, but keep the complete screen for final visual review. Locked keys (`translated` state) are read-only neighbours in every packet; proposals against them go to the audit findings, not the catalog.

## A. Forward translator

Dispatch with the coordinator packet, the locale brief (`references/locale-briefs/<locale>.md`), the whole voice card (`references/voice-card.md`; its money frame and persuasion limits are invariants, not style), the concept term block and the locale's examples file (a locale without one gets `references/examples-ro.md` as pattern illustration):

> Write the specified Moneyfesting screen or flow as the copywriter of a local product team for [locale/market]. Inputs: locale brief, voice card, concept term block, examples file, screen packet (IDs, source, screen and state with the screen's job and feeling, what the user just did and what the control does next, content kind, invariants, control role, slot and agreement target, width note, same-source siblings, neighbours). Process: (1) read the whole screen and its neighbours before writing a word; write functional and explanatory lines with every proposition kept, disclaimers and system-label mirrors in the brief's one approved form, promotional lines with the same promise in a local image and rhythm; (2) write each ID from its meaning using the brief's control form and the concept terms: reorder, change part of speech, split or merge, drop scaffolding ("Please", "In order to", "is:") and the English possessive habit; only the stated invariants (actor, action, condition, timing, amount/unit, negation, certainty, outcome) are fixed, so "Take back up to 3h" may swap "take back" for any local verb of getting your own time back, but never drops that outcome and never weakens "up to"; (3) re-read with the source hidden, rewrite anything a local user would recognise as translated, then restore any invariant you lost. Plain beats clever: a common expression a local understands on first read beats a rarer exact one. Where the source uses an image, use the local image that carries the same meaning and register ("raining cats and dogs" becomes "plouă cu găleata"); where none exists, state the meaning plainly rather than translating the image; never add an image the source does not carry. Buttons take the brief's control form; toggles and state labels take the local state form agreeing with the labelled noun; headers take the brief's header form; unit suffixes come from the brief's short-form table; an accessibility label is spoken, not shown: write one or two full sentences a person would say aloud, state or outcome first, units spelled out and numbers in a form VoiceOver reads correctly, no abbreviations, symbols or layout punctuation, and no shortening for fit; a composed prefix or suffix is written for its exact position and agreement target, and when no natural order exists, flag a merge into one key with a proposed format string instead of bending meaning. Reuse a same-source sibling's target when the control role matches, unless the examples file lists that target under Diagnosis: then write the listed candidate and flag the sibling for audit; diverge otherwise only with a consistency note naming the role difference. Emoji and exclamation policy comes from the brief. `Moneyfesting` and the brief's other fixed names stay exactly as written. Return per ID: target, control role and content kind, terms used, fit note (flag when longer than the brief's length trigger or when the control is a button, badge or widget line), rationale only for significant adaptations; plus glossary additions, source contradictions, and concatenation or agreement constraints. Do not edit shared resources. You are an AI language specialist, not a native person: do not claim native status or to have completed independent review.

Return one draft per ID, except hero-set IDs, which return three unranked candidates; an ID whose fit note flags length may add one compact alternative. Keep sentences that need agreement in one key and flag an engineering constraint when fragmented source strings prevent it. For a locale without an examples file, the first batch's deliverable also returns six target-language rows in the `examples-ro.md` format with the pattern column filled, which the coordinator saves as `references/examples-<locale>.md`.

Hero lines. The coordinator selects the hero set from the promotional register; current members are listed once in `references/surface-briefs.md` `## Hero set and candidate path` (snapshot 2026-09-15), and the coordinator takes that list, never a key pattern. Exclude brand-name titles, format-only keys, preview mock values and widget state labels. For each hero ID the coordinator writes a one-sentence frame from the source packet (worked briefs in `references/surface-briefs.md`). The translator returns three candidates with distinct angles (source-shaped; what a local team would write from scratch; the most compact that keeps the promise), none marked preferred, each within budget: same line count as source, carousel headlines six words or fewer, the accent-coloured fragment standing alone, no wrap at the smallest size before the view's own `minimumScaleFactor` engages (paywall hero: three stacked `Text` views under one 0.6 floor and no `lineLimit`, `OnboardingSubscriptionPaywallView.swift:315-325`, so each line must hold on its own). The editor's blind packet lists candidates in shuffled order; the editor ranks them for local, credible, clear next action and fits the control, with one reason line and no rewriting; a separate three-judge panel only when slots allow. The coordinator takes rank 1 unless back-translation shows a frame change; losers stay in the coordinator packet with one-line reasons. Shield example: `reflection.begin` "Begin before you're ready." ships as "Începe cu ce ai acum." (image changed, promise kept).

## B. Blind back-translator

Start fresh with the blind packet path only:

> Review this target-language UI for locale [locale/market]. Use only the supplied packet; do not read other files or seek the original wording. For every opaque ID, give a faithful English rendering of what is actually written, preserving ambiguity and awkwardness. Render meaning, not words: an idiom becomes the English idiom or plain statement with the same meaning ("plouă cu găleata" is "it is pouring", not "it rains with the bucket"), and a plain line stays plain. When a line carries an image, idiom or set phrase, give the meaning and then the literal wording in brackets ("it is pouring [lit. it rains with the bucket]"), so the coordinator can weigh the image against the source register without you seeing it. State any implied benefit, obligation, negation, amount or time relationship, and what a user expects each control to do. Do not repair the target or infer what the author intended. Flag unclear readings and confidence limits. Label each finding critical (changes an action, condition, amount or unit, negation, entitlement, permission or billing term), major (a local user would misread it or notice it as foreign or awkward), minor (only an editor notices) or preference, with one category: mistranslation, omission, addition, claim, terminology, grammar/diacritics, unnatural, register, calque, gender, placeholder, plural, markup, length, order; the packet's 1-5 naturalness scale is an extra per-line rating. You are an AI language specialist, not a native person: do not claim human or native status.

Back-translation is diagnostic evidence, not a second translation; the coordinator compares it under `## Reconcile and revise`. A rendering that differs from the source in rhetorical shape, sentence count, idiom or emphasis is never a finding by itself.

## C. Target-language editor

Start separately with the same blind packet path (hero candidates in shuffled order when the batch has them):

> Assess this UI as an AI language reviewer for everyday consumer-app use in [locale/market]. Read it in flow order without seeking the English original. Does it sound natural, familiar, relaxed and credible, and would a local user understand each line on first read? Method: benchmark each line against a well-made local app (Apple's own localization or a top local productivity app) and mark anything you would not expect there. Scan for imported shape: a possessive where the owner is obvious, source-language word order and noun stacks, a verb-for-verb rendering no local would say, a calqued noun, a feature personified the way English marketing does ("streaks that forgive"), capitalised words inside a sentence, straight quotes, a fragment where this language needs a verb, and any shape listed after this prompt. Check collocations. Idiom check: would a local say it this way; where a line carries an image or set phrase, is it one a local would use here, in this register, or does it read as someone else's image translated. Check every concept term against the packet's term list (`Moneyfesting` and Apple's product names in that list are fixed: an inflected, transliterated or translated form is a finding, the unchanged form never is; any form listed under `avoid` is a finding) and flag terminology drift between neighbouring lines of the same screen. Judge every line in its role: a button by the verb and object local buttons use and whether the user knows what happens next; a header or eyebrow by the form local headers take; a toggle or state label by agreement with its noun and by naming the term, not its own state; a `voiceover label` by reading it aloud, where an abbreviation, symbol or colon VoiceOver reads badly is major. Check fragment agreement against the packet's agreement target and small/medium variants of one state against each other; check that same-source siblings in the consistency section read as one control. For lines marked promotional, ask whether they could appear in a local App Store screenshot without reading as translated. Flag unsuitable slang, generic motivational filler, confusing money claims and register drift. When the packet carries a render or budget for an ID, judge fit against it and propose a shorter natural alternative that keeps the role; otherwise treat fit as unverified. Give exact issue spans, consequence and a suggested correction, and label each finding critical (changes an action, condition, amount or unit, negation, entitlement, permission or billing term), major (a local user would misread it or notice it as foreign or awkward), minor (only an editor notices) or preference, with one category: mistranslation, omission, addition, claim, terminology, grammar/diacritics, unnatural, register, calque, gender, placeholder, plural, markup, length, order; the packet's 1-5 naturalness scale is an extra per-line rating. For hero candidates, rank for local, credible, clear next action and fits the control, one reason line, no rewriting. Report no findings when that is the honest result. You are an AI language specialist, not a native person: do not invent a native-human credential.

The coordinator appends the brief's imported-shape list to this prompt in target-language form only, because the packet's `markers` are per-ID flags. The editor proposes; it never silently replaces the reviewed draft. For shared Arabic, check Saudi suitability and broader Gulf readability without claiming every Arabic-speaking audience has identical preferences.

## Reconcile and revise

For each finding record ID/variation, candidate revision, severity and category from the scale in `## Acceptance and evidence`, evidence, user impact, proposed fix, disposition and reviewer role. The coordinator compares source intent, observed behaviour, the back-translation and the editor findings, then the translator revises with that feedback; resolve a locale term across every occurrence of the concept.

Comparison rule: compare propositions, never words, word overlap or an embedding score. Ask of each ID: same actor, action, condition, timing, amount and unit, negation, certainty and outcome; same effect promised by the control. If the source used an image, is the local image equivalent in meaning and register: "plouă cu găleata" back-rendered as "it is pouring" is an acceptable adaptation of "raining cats and dogs". Check the reverse too: an image or set phrase in the target (B's bracketed literal) where the source is plain is an addition on functional, disclaimer, billing, permission, shield and accessibility copy and a register question for the editor on promotional copy; a source image carried word for word into a phrase no local uses is a calque, never fidelity, even when the propositions match. Label an ID match when the back-translation restates the source closely; classify every other difference as forward error (the target says something else), backward error (the back-translator misread a correct target; confirm with a second fresh B when the ID is tier A), acceptable adaptation (same propositions, local shape), or unresolved ambiguity (the target admits two readings; rewrite). On style the editor wins; on claims the back-translation wins; the coordinator records which rule decided.

Claim-ledger row (defined in SKILL.md `## Build context before words`): a claim true in the source locale but not the target is rewritten or dropped and the row records why. Examples (snapshot 2026-09-15): `money()` hardcodes USD (`OnboardingSubscriptionPaywallViewModel+LocalizedStrings.swift:14`), so ro time-value copy never names lei; `paywall.lastChance.urgency` "lowest price we offer" needs a row against `PaywallLadder.discountPercent(for:)`; `paywall.onboardingSubscription.annualPlanBadge` hardcodes 56% while `PaywallLadder.annualSavingPercentVersusWeekly` computes the live value (source defect: flag, do not fix); `paywall.onboardingSubscription.heroLineThree` "Start free." shows while `PaywallLadder.hasProducts` is false, so "free" means the free path, never a trial.

Shorten for fit. When render evidence or the layout tests report shrink, extra wrapping or overflow: functional copy drops what the brief marks droppable (fillers, articles), then the object the icon or row already names, then uses the brief's short form, then a shorter synonym with the same action and certainty; marketing copy cuts intensifiers and second adjectives, then the second clause, then swaps the image for a shorter local one; always keep deliberate source line breaks and the claim's condition. Accessibility labels, VoiceOver strings and share-card accessibility text are exempt from shortening and spell units out (`widgets.focusRing.a11y.*` "min." is the live violation; `ManifestingTests/Widgets/FocusRingCopyTests.swift` `romanianAccessibilityLabelsAvoidTheCountedNoun` pins the abbreviation today, so the fix is `ro` plural variations plus that assertion change, an owner decision listed in the report). Shortening may cut words, never facts; a fact that must go moves to a neighbouring element and the key's comment says so. Verdicts use each view's own `minimumScaleFactor` and `lineLimit` (`references/surface-budgets.md`); never lower a floor or raise a line limit to fit copy, file a layout finding instead.

Changing the target invalidates its backward and editorial verdicts: recheck the changed IDs plus listed neighbours with fresh blind agents, since the old ones may now know the source. A global term change reopens every occurrence; a layout-only change needs new visual evidence; a source or behaviour change needs a new meaning comparison. Minors and preferences reach the translator only when the coordinator adopts them. Seek a user decision only for missing product intent or a true brand or content-policy choice, never for ordinary grammar fixes. When such a decision, or a test that pins a form, blocks one part of a string, revise everything that does not depend on it in the same round and hold only that part.

## D. Final adjudicator

Dispatch a fresh reviewer after revisions and the technical and visual checks, with the coordinator evidence paths, the locale brief, the voice card, the glossary and the examples file:

> Independently decide whether this exact candidate revision is ready for the requested scope. Review the source and its actual UI behaviour, the target flow, the blind back-translation, editorial findings and resolutions, glossary, placeholders and plurals, the claim ledger, and rendered screen evidence. Challenge misleading time or money claims, changed actions or purchase conditions, mistranslation, unnatural or translated-sounding copy on any screen (hero, paywall, permission and shield lines first), a source image carried literally or an image added to plain copy, register drift, quote provenance, RTL and accessibility issues, stale review evidence, and any claim-bearing string without a ledger row. Classify round-trip discrepancies instead of demanding identical English; an idiom rendered as its local equivalent is an acceptable adaptation. Give concrete findings with the severity and category list the coordinator supplies from `## Acceptance and evidence`, and a verdict per quality dimension and affected screen/locale. Distinguish checked evidence from unavailable evidence. Do not count earlier approvals as proof and do not introduce unreviewed final copy. You are an AI language specialist, not a native person: do not present your verdict as native or human review.

Material changes it requests go back through the affected earlier stages within the same two-round budget, then it verdicts the resulting revision; the budget does not reset after a rejection. The coordinator is not a substitute for this pass; with no delegation available, report D `not_run`.

## Acceptance and evidence

Severity: critical = changes an action, condition, amount/unit, negation, entitlement, permission, billing term or provenance, or breaks the resource at runtime; major = a local user would misread it, notice it as foreign or awkward, or see clipping or truncation; minor = visible to an editor only; preference = a valid alternative. Material = critical or major. Categories per dimension: meaning (mistranslation, omission, addition, claim); editorial (terminology, grammar/diacritics, unnatural, register, calque, gender); structure (placeholder, plural, markup); visual (length, order); provenance stays its own category. A dimension passes with zero unresolved material findings in its categories; minors and preferences never block; the adjudicator may raise clustered minors on a hero, paywall, permission or shield screen to major with a stated reason; a role without evidence for a category records `not_checked`, never minor. The B and C prompts carry this scale verbatim, since blind agents cannot read the skill and the packet's `scale` is only the per-line naturalness rating.

| Dimension | Pass evidence | Blocking examples |
|---|---|---|
| Meaning and behaviour | Blind rendering for the claim-bearing tier, coordinator source comparison for the rest; ledger rows present; discrepancies classified and resolved | Earnings confused with time value; wrong negation, unit, amount, CTA, entitlement, billing period, permission or condition |
| Locale and editorial quality | Separate target-only flow review with the method in C; concrete findings resolved | Literal or translated-sounding syntax, calqued image, mixed regional variants or register, mistranslated core concept, offensive or misleading adaptation |
| Structure and runtime | `catalog_check.py` and `term_audit.py` pass, build and consuming targets checked, per-language width and claim suites green where they exist (`references/project-context.md` `## Verification hooks`) | Lost or type-changed placeholder, wrong argument binding, missing reachable plural, broken markup, wrong bundle or fallback, stale language cache |
| Visual and accessibility | Exact candidate rendered on relevant screens and sizes, judged at each view's own floor; RTL and VoiceOver checked where applicable | Clipping, unreadable abbreviation, misleading truncation, scrambled number or currency order, unusable reading order |

Use `pass`, `fail` or `not_checked` per dimension; `not_applicable` needs a scope reason. Never average failures away. An unresolved material finding prevents calling that screen/locale ready; unchanged languages may still be complete. A `prepare` run completes its brief without runtime checks but never labels the locale ready to ship. On integration write every AI-written or AI-revised unit with `state: needs_review`; `translated` means owner-accepted. Shield Swift pairs have no state field: list AI-revised ids in the report.

Record the candidate revision or hash, covered IDs and variations, role identities and actual settings, substantive findings and resolutions, commands and results, screenshot paths with device/locale/state, the run directory and the catalog commit. For imported review evidence, role labels alone do not establish human or AI identity, native fluency, model settings or isolation; leave those facts unknown when unsupported.

## Human review

A recommendation, never an order. Recommend a native read of the prominent creative copy (hero set, store metadata, shield pairs) when: first ship of a locale; an adjudicator preference finding on a hero ID stays open; the brief was built without a native source. When the requester identifies as a native reader of the locale, emit a review packet instead: rows `{id, screen, control, target, one-sentence intent, screenshot, question}` plus the word total, inside `coordinator/`. Ingest returned comments as findings with role `human` and provenance "human, uncertified"; they open one extra round with fresh blind rechecks of changed IDs. A recommendation is not a blocking finding. Report line, always present: `human review: recommended (<n> strings, ~<w> words) | done by <who, date> | not needed because <reason>`.

Every role in this protocol is an AI language specialist, not a native person; blindness is context isolation, not independence; and no stage produces human approval. Never write that a human reviewed copy unless a record with a named source exists.
