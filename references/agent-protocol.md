# Agent protocol

How the coordinator runs the translator, the blind reviewers and the adjudicator for one Moneyfesting locale. SKILL.md says when to read this file and describes the scripts named here.

Contents: Hosts · Roles and scheduling · Model routing and cost · Tiers, order and batches · Quote corpus · Packet separation · A. Forward translator · B. Blind back-translator · C. Target-language editor · Reconcile and revise · D. Final adjudicator · Acceptance and evidence · Human review

## Hosts

Use the host's subagent tools, not user-visible new tasks. Blind stages require a source-free review context. Start without prior conversation, then check the host-supplied context; a fresh spawn alone does not establish blindness:

| Need | Codex | Claude Code |
|---|---|---|
| Fresh blind reviewer (B, C, hero judges) | `collaboration.spawn_agent` with `fork_turns="none"`; prompt = role text plus the path to `blind/target.rev<N>.json`, nothing else | Agent tool, a new non-fork subagent; same prompt and path, with startup context checked |
| Fresh adjudicator (D) | same spawn; prompt = role text plus the `coordinator/` evidence paths | same |
| Continue the translator for rev2 | `send_message` / `followup_task` to the translator | `SendMessage` to the original translator where the host supports resuming it; otherwise a fresh Agent call with its packet, candidates and dispositions |
| Parallel B and C re-runs, or three or more locales | several spawns in one turn | several Agent calls in one message; the Workflow tool only when the user has opted into workflows |
| No delegation available | do A yourself; mark B, C and D `not_run`; never grade your own draft as blind | same |

Both hosts: never pass this skill, its name or the conversation to a blind agent, because the skill text itself carries English product context; a host may still list this skill's name and description in the agent's tool list, which is why the role prompt says to use only the packet. Before dispatch record role, locale/market, model alias or `unknown`, primitive used, and the exact source and candidate revision; the report's Reviews line repeats the primitive (`Agent` or `spawn_agent`) and the alias.

Before the first blind dispatch on a host, inspect its startup rules, preloaded skills and persistent memory for source text or earlier judgments. Claude Code can load `CLAUDE.md` into a new subagent; where supported, use `omitClaudeMd: true`, no source-bearing preloaded skills and no persistent reviewer memory, while preserving applicable permissions. Codex `fork_turns="none"` excludes conversation history; inspect the effective role and inherited project guidance separately. Record known exposure and unknowns with the dispatch. A packet leak scan checks known strings, not semantic paraphrases, images or hidden host context. If source material reached the reviewer, discard the blind claim and use a fresh isolated review. Host settings must be verified against the installed version, not assumed portable between products.

Project agent specifications live in `.codex/agents/*.toml`. These are separate from `agents/openai.yaml`, which describes the skill in the UI. For Codex project discovery, run `scripts/install_project_agents.py --app-root <worktree>` to preview deployment, then `--apply` to place the files in that app worktree's `.codex/agents/`; installing the skill alone does not deploy them. Use the named role when the host exposes custom-agent selection. When the spawn tool has no named-role selector, read that role's `developer_instructions`, pass them explicitly with only its allowed packet, and set its recorded model and effort. This fallback tests the instructions, not automatic discovery. Claude Code uses fresh Agent calls with explicit role instructions and its available models; the Codex TOML aliases do not select Claude models.

Route app screens to `app_localizer` and target-only flows to `app_copy_editor`; use `quote_translator` for authored/curated affirmations, `literary_translator` for attributed material, and `quote_researcher` for bounded source checks. Corpus reviews use `quote_editor`, `quote_fidelity`, optional `quote_backtranslator`, then `quote_adjudicator`. Model settings in those files are pilot choices, not demonstrated language rankings. Quote roles must not inherit the app's plainness rule for literary passages. Freeze the specification and packet before comparisons; compare generic and specialized instructions with the same model/effort and unseen inputs, recording unnecessary edits as well as missed errors. Do not tune on the held-out set and then report it as independent validation.

## Roles and scheduling

The coordinator (the agent running the skill) owns context gathering, packets, meaning comparison, integration and technical evidence, and writes no target copy while delegation exists. UI runs use four distinct agents: A forward translator, B blind back-translator, C target-language editor, D final adjudicator; literary corpus work adds the bilingual reviewer below. A completed translator is never its own reviewer; an agent that has seen the source is never dispatched as blind; contamination discards the blindness claim and costs a fresh spawn.

Run C before B on every revision: the editor finds the shape and naturalness problems that force rev2, so back-translating rev1 would pay for the same IDs twice. Run B and C in parallel only when re-running an already passed batch. Locales proceed concurrently within available slots; dependent reviews wait for their actual input; with few slots, schedule in waves and merge `glossary_adds` between waves.

Modes: `prepare` dispatches nobody. `audit` dispatches C and D over the shipped copy (plus bilingual review for literary records) and returns findings as proposals, applied only for keys the user names. `translate` runs the full order below. `en` audit runs as SKILL.md `## Establish the assignment` describes; applying an accepted en change also updates the call-site `defaultValue` and re-runs the affected ro checks in the same change set.

## Model routing and cost

Honor the user's model choice and inspect the host's available aliases and effort settings before dispatch. The following Codex routes are pilot hypotheses for the current runtime, not evidence that a model is the best translator in any language:

| Work | Pilot route |
|---|---|
| Counts, hashes, schema, placeholders, duplicate IDs and coverage | Deterministic scripts; inspect failures before involving a model |
| Authored affirmations, UI translation and target-only UI review; bounded provenance research | `gpt-6-sol`, high effort, separate fresh reviewers |
| Diagnostic back-translation | `gpt-6-sol`, medium effort |
| Literary translation and editing, bilingual fidelity review, final adjudication and unresolved meaning | `gpt-6-astra`, high effort, separate fresh reviewers |
| Low-risk preparation summaries, if useful | `gpt-6-luna`, medium effort; no linguistic acceptance verdict |

Do not default to maximum effort. If an alias or effort is unavailable, use an available setting and record the substitution; Claude Code uses its actual available models, not these aliases. Keep isolation unchanged when changing models. Different aliases do not establish statistical independence.

Compare routes on the same representative pilot and resolved findings before expanding a locale. Record actual model/effort, elapsed time, input/output tokens when exposed, review coverage and revision count. Project a cost range from that pilot's word count and observed retries; use verified current prices only when quoting money. Missing usage or price data stays unknown. A cheaper route is a candidate only if its checked quality dimensions still pass.

## Tiers, order and batches

Tier each ID from `catalog_check.py` output before dispatch. A = claim-bearing: money, billing, entitlement, permission, deletion, negation, amount/unit, every plural and `*.a11y.*` variation, and keys under the risk prefixes `paywall`, `screenTime`, `screenTimeReport`, `streakFreeze`, `notifications`, `insights`, `moneyfesting`, `currency`, `onboarding.hourlyWage`, `onboarding.income`, `onboarding.*Permission*`. B = expressive or simple functional. C = single-word controls. Back-translate A in full (the 35 ro plural keys and the a11y keys are cheap), plus shield pairs and paywall/permission hero lines whatever their tier; B and C only when the editor or coordinator records a meaning doubt.

Order per batch: (a) script gate (`catalog_check.py`, `term_audit.py`); (b) for batches with widget, shield, accessory or single-line CTA strings, integrate rev1 in the authorized app worktree and render it in the target language before language review, so fit is known before the editor spends a round on wording; keep provisional edits within the coordinator's scope and replace them with the reviewed candidate before final integration; (c) target-language editor on the blind packet, with hero ranking; (d) dispositions, translator rev2; (e) script gate; (f) rebuild the blind packet from `candidates.rev2.json`, then a fresh editor on changed IDs plus listed neighbours; (g) blind back-translator on rev2 for the tier; (h) coordinator meaning comparison; (i) integrate, render, adjudicate. Two material revision rounds per batch, including changes the adjudicator requests; fit-only shortening that changes no invariant is not a material round but re-runs the editor on the changed IDs. The coordinator may forward the editor's suggested line to the translator as the preferred rev2 candidate after checking the invariant list; the editor still does not replace the draft. When the budget is exhausted with a material finding open, hold that scope as incomplete and finish unaffected work.

UI response gate: before using a translator or editor result for a flat ordinary-UI packet, run `scripts/ui_review_check.py --role translator|editor --packet <source-or-blind-packet> --result <role-result>`. It validates locale, numeric revision, exact assigned-ID coverage, verdict fields and nonempty uncertainty notes; their adequacy still needs review. A structural pass is not language acceptance. Repair missing or malformed output before advancing. Hero alternatives, plural branches and nested units are outside this checker's current scope: retain their existing explicit per-candidate/per-unit review and record the automated contract gate as unsupported, never passed. Freeze each dispatched packet and result with its hash; changed text or decision-bearing context needs a new revision and affected rechecks even if a file was mistakenly left at the old revision number.

If a shared build slot temporarily blocks those renders, C may review language first with fit marked `not_checked`. Resume the visual check when the slot opens; changed copy follows the same revision rules. This scheduling exception does not waive the rendered pilot or final acceptance gates.

Batches: 15-40 IDs from `worklist.py`; 20 or fewer for paywall, permission and hero batches; shields one batch of pairs; widgets by family. Re-review an `unchanged_passed` key only when a glossary change lists it, runtime or language evidence reveals a defect, or the user requests a full audit; log the skipped count. For a new defect, record the evidence and use an explicit key list covering the affected equivalent states.

Pilot first. Administrative edits to coordination, paths or installation do not require repeating linguistic benchmarks. For a locale's first run, and after a change to translation behavior, the locale brief, or glossary entries that fix control forms, run one batch alone through every stage (build and tests per the app `CLAUDE.md`, render evidence at relevant widths and supported text sizes, adjudicator verdict) before dispatching other batches. Selection: one widget family with plurals and a11y keys, the paywall hero lines, one streak variant pair, three shield pairs, about 20 IDs, prefer `needs_review`; use the live `worklist.py --pilot` output. The 2026-09-15 member list (`widgets.focusRing.*`, `paywall.onboardingSubscription.heroLineOne/Two/Three`, `widgets.streak.copy.frozen.small/medium`, and `companion.space`, `companion.next_step`, `companion.on_your_side`) is historical. The ro pilot runs in `translate` mode limited to `needs_review` keys, so every stage runs while the owner lock keeps `translated` units untouched (SKILL.md `## Translate and review`); a pilot in `audit` mode stops at the script gate, the editor and the adjudicator, since nothing is integrated there is nothing to build or render. Treat its findings as corrections to the brief and glossary, apply them before the next batch and list them by category in the report; proceed on pass, stop on fail or when a new-locale brief needed changes. Record `GIT_OPTIONAL_LOCKS=0 git status --porcelain` in the run record (the variable keeps git from rewriting the checkout's index); stop only if a file this run will edit is already modified.

## Quote corpus

Use this path when the requested scope includes quote content. Read the live `Data/quotes/SCHEMA.md` and the Content policy in `references/project-context.md` first. These content rules and role prompts supersede UI plainness, hero candidates and marketing shortening for corpus records; controls around a quote still use the UI path.

### Reconcile all locale inventories

Start from the union of every existing locale's records, including locale-only material. Align counterparts using explicit `pairId`, `translationOf` or verified canonical references with matching passage spans; preserve each locale's IDs, text and metadata. English is one inventory, not a filter for what survives. Semantic similarity, near-synonyms or a shared author do not establish identity: distinct phrases stay distinct even when they express the same idea.

Carry every distinct item into the reconciliation manifest. If translation makes two distinct records identical in the target, revise the new candidates to retain their supported distinctions or record the ambiguity; never delete or merge a record to clear the collision. Preserve existing shipped and owner-accepted wording while the decision is pending.

Any proposed exclusion or merge that loses distinct content needs an explicit user decision. First present concise examples, affected record and locale counts, and the effect on coverage and the reader's pool. If the exact action is already authorized, carry it out without asking again. Ordinary translations and preservation of existing records need no new confirmation.

### Classify before drafting

| Kind | Treatment |
|---|---|
| Verified app-authored affirmation or curated text | Transcreate the reader's voice, imagery and rhythm within the original meaning, intensity and money-frame rules; preserve pair links |
| Attributed or other literary quotation | Preserve author voice, deliberate ambiguity, imagery, repetition, contrast and rhythm; use a sourced published translation when available and permitted by the live policy |
| Scripture | Match the canonical reference to the approved published target-language edition; record edition and wording provenance; never generate a substitute translation |
| Unknown authorship, source or translation provenance | Preserve the record and its current status; queue the verification question. Hold only proposed verification upgrades or new publication lacking required evidence; never remove or unpublish existing content automatically |
| User content | Leave unchanged |

For attributed translations preserve the original text, original language, author, source and existing verification status. Record any intermediate English translation: it is not the original when the work was written in another language. Keep the target's published-translation citation or AI-translation status distinct. Translation linkage and provenance belong in internal metadata; visible translation notices follow the owner's no-notice policy in SKILL.md. An independently necessary exception requires the owner's explicit approval before implementation.

Verification lookup: inspect the supplied source first, then use at most three targeted searches per uncached work/reference before recording `not_found` and the remaining question. Cache retrieved evidence by author, work, edition and language, and record-level verdicts by reference and text hash; reuse them across batches and invalidate changed evidence. Keep queries, inspected citations and dates. `not_found`, unavailable evidence and `disproven` are distinct findings; a wording mismatch with one published translation is not disproof. Check edition, reference, passage context and intermediate translations before judging attribution. Missing author metadata alone never establishes app authorship.

### Corpus packets and review

The coordinator packet includes stable record ID, category, content kind, source and original language, available surrounding passage, intended sense and ambiguity, attribution/provenance, pair links, target locale, display surfaces and constraints. Unknown context stays unknown. Blind packets retain opaque IDs, target text, content kind and neutral display roles; source text, author identities that reveal the source, translator rationale and earlier verdicts stay coordinator-side. Generate corpus packets with `scripts/corpus_run.py` and apply the fresh-context checks before dispatch. Catalog checks do not establish corpus coverage.

### Staged execution

`scripts/corpus_inventory.py` reports the union using explicit links; `scripts/corpus_run.py` creates additive staged exports. Both read the original corpus without rewriting it. A run needs a local corpus JSON and relevant context files. Supply `--categories` at initialization to limit work, and repeat `--context` for voice, policy and locale evidence; `ro=file`, `hu=file` and `category:religion=file` scope a context file. Include every decision-bearing brief or glossary so a change invalidates its affected jobs.

```sh
python3 scripts/corpus_run.py init --corpus "$CORPUS" --run-dir "$RUN" --locales en,ro,hu --context references/voice-card.md --context ro=references/locale-briefs/ro.md --context hu=references/locale-briefs/hu.md
python3 scripts/corpus_run.py batch --run-dir "$RUN" --locale hu --size 20
python3 scripts/corpus_run.py ingest --run-dir "$RUN" --batch b0001 --candidates "$CANDIDATES"
python3 scripts/corpus_run.py review-packet --run-dir "$RUN" --batch b0001 --role editor
python3 scripts/corpus_run.py review --run-dir "$RUN" --batch b0001 --role editor --input "$REVIEW"
python3 scripts/corpus_run.py status --run-dir "$RUN"
```

The first batch command returns its source-packet path. Dispatch by content kind; preserve raw agent results. Normalize their per-ID proposals into the packet's `output_contract`, retaining substantive uncertainty and findings in `notes`, and record the actual execution identity/model/effort. Never invent a pass while adapting the schema. A role hold is unresolved work, not an empty or fabricated translation: leave the batch pending until the held IDs can be resolved. Review packets require complete candidate coverage. Repeat the packet/review commands for `fidelity`, optional `backtranslation`, then `adjudicator`; use fresh isolated agents, never reuse translators as reviewers. A diagnostic back-translation has no fidelity verdict; store it as `not_checked` with its rendering in notes. Declared identities are not authentication or proof of isolation.

Pending batches reserve their jobs; resume the existing packet instead of submitting duplicate work. Identical retries keep reviews. For a revision, run `batch --revise --locale hu --job <group::locale>` (repeat `--job` for affected jobs); this supersedes earlier batches and changing a candidate invalidates its reviews. `sync` re-reads source/context files and retains only jobs whose fingerprints match; it refuses missing original IDs. Review packets bind an opaque revision token to the exact candidate and context; adjudication also binds the earlier review evidence.

Export with `export --run-dir "$RUN" --out "$NEW_FILE" --locales hu --categories affirmations`. The destination must be new and outside the run. It keeps the full original envelope and every original record, then adds reviewed counterparts for the complete selected categories. Unknown eligibility, missing reviews/context, or unresolved identical-target collisions block additions without removing anything. `status` exposes collision IDs; revise the new wording or use `acknowledge-collision --collision <id> --reason <rationale>` to retain both distinct records explicitly. This never authorizes a merge or exclusion.

Scripture additionally needs `--canonical <index.json>` on init/sync. Its `entries` contain `locale`, `reference`, `edition`, `text`, `source_url`, `corpus_sha256` and `complete_verses: true`; exact candidate equality is enforced. The index must come from an inspected approved edition and complete consecutive verses. The script validates the supplied evidence, not the publisher's identity or rights. New targets carry `pending_owner_review`; staged success is not publication, a native benchmark, or a fit verdict. The current app still needs Hungarian bundle support and review of reverse-language links before integration. The existing visible translation suffix is scheduled for removal during the later quote corrections, under the owner's display decision.

Literary translator prompt (A):

> Translate the supplied literary passage into [locale] using the source and provenance packet. Preserve its meaning, authorial voice, imagery, deliberate ambiguity, repetition, contrast and emotional intensity. Write idiomatic target-language literature without turning the passage into app instructions or generic motivational prose. Familiarity is not a reason to replace an author's distinctive image. Record unavoidable losses or competing readings, and distinguish the original from any intermediate translation. Return one candidate per ID with uncertainty notes and display concerns; do not shorten or silently modernize an attributed quotation to fit a widget.

Literary editor prompt (C), replacing the consumer-app editor prompt:

> Review only the supplied target-language literary packet for [locale]. Assess syntax, collocation, rhythm, coherence, register and emotional effect. Distinguish a possible literary choice from an accidental calque; unusual imagery or ambiguity alone is not a defect. Explain the reader impact of each proposed change. Do not flatten the voice into familiar app copy, seek the source, or claim source fidelity. Use supplied target-only literary examples if present; otherwise label your register assessment an AI judgment without an external benchmark. Return concrete findings or no findings using the supplied severity scale.

A separate bilingual reviewer checks **every literary item**, including curated literary text, against the source after the editor's revisions. It receives both texts and provenance, is explicitly not blind, and uses this prompt:

> Compare each final target with the supplied source and available original. Check omissions, additions, agency, negation, modality, logical relationships, voice, imagery, deliberate ambiguity and intensity. Name the exact lost or altered effect and its consequence; accept different wording that preserves it. Flag uncertainty from missing context or an intermediate translation; if only that intermediate text is available, original-language fidelity stays not_checked. Verify attributed text and scripture against the cited source or edition; different wording alone does not disprove attribution. Preserve distinct records with similar meanings and flag translation-induced identical targets for revision or a recorded ambiguity. Record pass, fail or not_checked per ID and candidate hash; never claim verification from a citation you have not inspected or recommend deletion merely because verification is incomplete.

Keep B as a diagnostic for claim-bearing or disputed items; back-translation alone cannot establish literary fidelity. Resolve literary tradeoffs with the bilingual evidence and C's target-language findings, then give D the exact final revision and both reviews. A missing bilingual check leaves literary fidelity `not_checked`. Scripture uses provenance and exact-edition verification instead of creative revision. Select only complete consecutive verses permitted by the live corpus policy, inspect surrounding context, and update the displayed reference to match; never shorten inside a verse to fit.

### Batches, resumption and integration

- Run one representative corpus pilot per locale before fan-out: cover each included content kind, short and long items, metaphor, ambiguity, culturally specific language and constrained display surfaces. Start with 15–25 records grouped by kind and author or theme; adjust by word count and observed review load.
- Store `coordinator/corpus-manifest.json` with all locale snapshots, the union of required category records, explicit counterpart links and preserved per-locale IDs; include per-record source/target hashes, context/brief/glossary/policy versions, existing and proposed provenance status, batch, candidate revision, review coverage/findings, display evidence and completion state. Checkpoint after each stage; keep rejected candidates outside blind packets.
- Resume only records whose source, target, relevant brief/glossary and policy inputs match their passed evidence. Reopen affected records on changes; count and report reviewed, unchanged, held and remaining records separately. Before merging each batch, require exact agreement between expected and returned IDs, with no duplicates, omissions or unexpected IDs; check pair links and metadata preservation as well.
- Stage completed batches against the declared union, preserving the existing shipped category. Before activating a proposed category release, account for every required record and pass the applicable content/runtime/display checks; incomplete new target pools must not silently replace a larger existing fallback pool. A held proposal does not remove existing records or make a shipped category disappear. Count retained records as unchanged, not newly verified; keep their current status, report unresolved questions separately and apply exclusions only under the decision rule above.
- Preserve full literary text. Track display eligibility separately for quote cards, widgets, notifications and sharing, including author attribution and any separately owner-approved notices. Check actual layout behavior and render longest and boundary cases; an overflow calls for a layout or explicit display-selection decision, not an unmarked abridgment.

Report corpus language review, provenance, category coverage and app/display readiness separately. An AI-reviewed corpus is not human-benchmarked. Recommend a named target-language reader review a representative pilot, with bilingual competence for fidelity judgments; record the sample, language background as reported, date and findings. Without that evidence, human benchmark remains `not_checked` and no claim of equivalence to human review or validated native quality is made; the recommendation itself is not a new approval gate. To evaluate professional quality, compare held-out outputs with qualified human translations of the same brief in randomized, anonymous order. Use bilingual reviewers for fidelity and target-language readers for naturalness; record material errors, preference and editing effort per language. A small pilot guides improvements but does not establish universal indistinguishability.

## Packet separation

Run state lives under `<checkout>/.codex-tmp/localization/<locale>/<run-id>/` (gitignored, snapshot 2026-09-15), one opaquely named `<batch>/` folder per batch (`b01`, since the blind agent receives the path) as `build_context_packet.py --out-dir` writes it: `coordinator/` holds `source.json`, `candidates.rev<N>.json`, `findings.json`, `worklist.json`, `id_map.json`, `verdict.json` and `leak_check.txt`; `blind/` holds only `target.rev<N>.json`; run-wide files sit in `<run-id>/coordinator/` (SKILL.md `## Establish the assignment`). `scripts/build_context_packet.py` writes both from the catalog for rev1; for every later revision pass `--candidates coordinator/candidates.rev<N>.json --rev <N>` so the blind packet carries the candidate text, which also re-runs the leak check before dispatch and keeps the hand-completed `screen_state`, `invariants`, casing context, evidence and fit of every key whose English units and comment did not change. A failing leak check blocks dispatch of B and C, and blind agents receive exactly one path, never a hand-edited file, to keep catalog snapshots and opaque IDs consistent.

The blind packet carries: locale, neutral `screen_role`, rev, order, per string `{id s01.., text, plural, control_role, tokens with neutral samples, fit when supplied}`, a `consistency` section after the flow (same-source siblings as target text with role), a target-only term list (`use`: fixed names and glossary preferred forms; `avoid`: the glossary's forbidden forms; no English definitions), per-ID markers (plural, fixed name, uppercase by design, identical by design, no target yet, attributed or user content), a per-line naturalness scale (the severity and category list travels in the role prompt), and target-language screenshots if available. Opaque IDs map to repository keys only in `coordinator/id_map.json`. The brief's imported-shape markers and the target-language banned words from its `## Money frame` travel as lines the coordinator appends after the editor prompt, never as edits to the packet file.

Keep out of it: English originals, source-bearing keys or filenames, English glossary definitions, source-derived wording hints or intended interpretations, translator rationale, prior findings or verdicts, the examples file (its EN column breaks separation), and source text inside images; do not hide a source string in a supposedly neutral screen title. Include neutral, verified action and dismissal descriptions so the editor can distinguish controls; describe behavior without suggesting the translation. Keep brands and untranslatable identifiers that appear in the actual target UI. Tell blind agents not to read the repository, other run artifacts, or search for Moneyfesting's source wording; this is context isolation, not a claim of filesystem sandboxing or statistical independence between models. Retain rejected candidates outside the blind packet.

Every scoped ordinary-UI entry carries `casing`: status, UI role, position, style, capitalization owner, protected target terms and documented exceptions. Optional equivalent groups compare controls with the same role; optional transforms record the operation and its call site. Generated metadata remains `needs_review`: neither a key suffix nor source capitalization confirms the role. Confirm the locale's rule against the actual composition and transform before dispatch. Attributed and user content explicitly use justified `not_applicable`. The blind projection contains only status, role, position, style, owner, protected spellings, exception texts, opaque equivalence groups and transform operation; rationale, source evidence and paths stay coordinator-side and all supplied target text passes the leak check. Unit overrides inherit key-level context; nested target branches travel with opaque unit IDs matched to their casing, while canonical unit paths and source/target snapshots stay coordinator-side. Unsupported nested candidate edits fail instead of reusing stale branch text. Primary casing describes the default display use; `casing.occurrences` inherits that context with overrides for additional roles and travels blind under opaque occurrence IDs. For `owner: view`, style describes the rendered text: C12 requires coordinator-only `transform.operation`, `file`, `line` and observed `catalog_value`, `rendered_value`, `render_locale`, `render_status: pass`, `render_evidence`; never synthesize this evidence with Python uppercasing, and supply actual images or target-only rendered text separately to blind C.

`debugOnly`, `previewOnly`, `shadow` and format-only keys (the `catalog_check.py` exclusions) never enter translation or blind packets; list them as not user-facing. A literal, user-reachable key is translated with a scoped engineering note to add a namespaced key. Format-only keys are not translated; verify separator and order conventions per locale (` · `, `/`, `, `, `:`) from the widest sample. Identify untranslated quotations and user-content blocks separately from translated IDs and exclude them from blind verdicts; redact them in blind evidence if they reveal the tested source, but keep the complete screen for final visual review. Locked keys (`translated` state) are read-only neighbours in every packet; proposals against them go to the audit findings, not the catalog.

## A. Forward translator

Dispatch with the coordinator packet, the locale brief (`references/locale-briefs/<locale>.md`; its `## Money frame` gives the target forms of the voice card's money frame), the whole voice card (`references/voice-card.md`; its money frame and persuasion limits are invariants, not style), the concept term block and the locale's examples file (a locale without one gets `references/examples-ro.md` as pattern illustration). Verified source meaning and app behavior remain authoritative. Resolve evidence by its role: verified behavior defines the action and claim; owner decisions and approved system mirrors govern their exact scope; the locale brief and glossary govern local conventions; examples and comparator screens illustrate rather than override them. When source text contradicts behavior, record a source defect before drafting that claim. A conflicting style example does not silently replace an approved term; record a scoped decision and reopen affected occurrences. Accepted related-language copy may clarify an ambiguity or show a possible strategy to the coordinator and translator, but is neither a default pivot nor proof of natural target copy; never send it to the blind editor. Record provenance when an intermediate translation actually informs a candidate, then recheck the source invariants. Draft and review the requested target language directly; no extra comparison round is automatic:

> Write the specified Moneyfesting screen or flow as the copywriter of a local product team for [locale/market]. Inputs: locale brief, voice card, concept term block, examples file, screen packet (IDs, source, screen and state with the screen's job and feeling, what the user just did and what the control does next, expected register and tone, syntax role, content kind, invariants, control role, slot and agreement target, width note, same-source siblings, neighbours). Process: (1) read the whole screen and its neighbours before writing a word; write functional and explanatory lines with every proposition kept, disclaimers and system-label mirrors in the brief's one approved form (Money frame, Platform terms), promotional lines with the same promise in a local image and rhythm; (2) write each ID from its meaning using the brief's control form and the concept terms: use natural target-language order, including inversion or emphasis where appropriate, and reorder, change part of speech, split or merge, drop scaffolding ("Please", "In order to", "is:") and the English possessive habit; preserve actor, action, condition, timing, amount/unit, logical scope, negation, certainty, severity and outcome, so "Take back up to 3h" may swap "take back" for any local verb of getting your own time back, but never drops that outcome and never weakens "up to"; (3) re-read with the source hidden, revise imported shapes, then restore any invariant you lost. Leave natural, context-fitting copy unchanged. Plain beats clever: a common expression a local understands on first read beats a rarer exact one. Where the source uses an image, use the local image that carries the same meaning and register ("raining cats and dogs" becomes "plouă cu găleata"); where none exists, state the meaning plainly rather than translating the image; never add an image the source does not carry. ## Reconcile and revise

For each finding record ID/variation, candidate revision, severity and category from the scale in `## Acceptance and evidence`, evidence, user impact, proposed fix, disposition and reviewer role. The coordinator compares source intent, observed behaviour, the back-translation and the editor findings, then the translator revises with that feedback; resolve a locale term across every occurrence of the concept.

Comparison rule: compare propositions, never words, word overlap or an embedding score. Ask of each ID: same actor, action, condition, timing, amount and unit, negation, certainty and outcome; same effect promised by the control. If the source used an image, is the local image equivalent in meaning and register: "plouă cu găleata" back-rendered as "it is pouring" is an acceptable adaptation of "raining cats and dogs". Check the reverse too: an image or set phrase in the target (B's bracketed literal) where the source is plain is an addition on functional, disclaimer, billing, permission, shield and accessibility copy and a register question for the editor on promotional copy; a source image carried word for word into a phrase no local uses is a calque, never fidelity, even when the propositions match. Label an ID match when the back-translation restates the source closely; classify every other difference as forward error (the target says something else), backward error (the back-translator misread a correct target; confirm with a second fresh B when the ID is tier A), acceptable adaptation (same propositions, local shape), or unresolved ambiguity (the target admits two readings; rewrite). ## Acceptance and evidence

Severity: critical = changes an action, condition, amount/unit, negation, entitlement, permission, billing term or provenance, or breaks the resource at runtime; major = a local user would misread it, notice it as foreign or awkward, or see clipping or truncation; minor = visible to an editor only; preference = a valid alternative. Material = critical or major. Categories per dimension: meaning (mistranslation, omission, addition, claim); editorial (terminology, grammar/diacritics, unnatural, register, calque, gender); structure (placeholder, plural, markup); visual (length, order); provenance stays its own category. A dimension passes with zero unresolved material findings in its categories; minors and preferences never block; the adjudicator may raise clustered minors on a hero, paywall, permission or shield screen to major with a stated reason; a role without evidence for a category records `not_checked`, never minor. The B and C prompts carry this scale verbatim, since blind agents cannot read the skill and the packet's `scale` is only the per-line naturalness rating.

| Dimension | Pass evidence | Blocking examples |
|---|---|---|
| Meaning and behaviour | Blind rendering for the claim-bearing tier, coordinator source comparison for the rest; ledger rows present; discrepancies classified and resolved | Earnings confused with time value; wrong negation, unit, amount, CTA, entitlement, billing period, permission or condition |
| Locale and editorial quality | Separate target-only flow review with the method in C; concrete findings resolved | Literal or translated-sounding syntax, calqued image, mixed regional variants or register, mistranslated core concept, offensive or misleading adaptation |
| Capitalization | Every scoped ordinary-UI unit has confirmed casing context or justified `not_applicable`; automated check and independent candidate review pass, equivalent controls agree, exceptions are documented, and audited transforms match exact rendered candidates | Missing or ambiguous rule, same-role casing drift, damaged protected spelling, conflicting catalog/view transforms, or unverified display casing |
| Structure and runtime | `catalog_check.py` and `term_audit.py` pass, build and consuming targets checked, per-language width and claim suites green where they exist (`references/project-context.md` `## Verification hooks`) | Lost or type-changed placeholder, wrong argument binding, missing reachable plural, broken markup, wrong bundle or fallback, stale language cache |
| Visual and accessibility | Exact candidate rendered on relevant screens and sizes, judged at each view's own floor; RTL and VoiceOver checked where applicable | Clipping, unreadable abbreviation, misleading truncation, scrambled number or currency order, unusable reading order |

Use `pass`, `fail` or `not_checked` per dimension; `not_applicable` needs a scope reason. Never average failures away. An unresolved material finding prevents calling that screen/locale ready; unchanged languages may still be complete. A `prepare` run completes its brief without runtime checks but never labels the locale ready to ship. On integration write every AI-written or AI-revised unit with `state: needs_review`; `translated` means owner-accepted. Shield Swift pairs have no state field: list AI-revised ids in the report.

Record the candidate revision or hash, covered IDs and variations, role identities and actual settings, substantive findings and resolutions, commands and results, screenshot paths with device/locale/state, the run directory and the catalog commit. For imported review evidence, role labels alone do not establish human or AI identity, native fluency, model settings or isolation; leave those facts unknown when unsupported.
