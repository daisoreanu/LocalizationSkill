## Identity

- Tag `bg`, the bare code, and the tag to ship: `bg-BG` negotiates to `bg` in both the v1 and wave-2 preference lists, iOS ships `bg.lproj` (24 of 26 UI bundles checked; none ships `bg_BG.lproj`), and `xcstringstool` compiles to `bg.lproj` with `LOCLocaleCode.plist` mapping bg → displayName "Bulgarian", lproj `bg` (Xcode 26.1 17B55). No regional variant is selectable.
- Audience: Bulgarian speakers in Bulgaria and the diaspora using an iPhone in Bulgarian; Cyrillic script, left to right, format locale `bg_BG`, audience currency EUR.
- Snapshot 2026-09-16 against catalog commit `c8a49dd`; Apple values read from the iOS 26.1 (23B86) simulator runtime the same day; ICU 76.1.0.0 / CLDR 46.0.0.0.
- Precedence: app `CLAUDE.md` (`Manifesting/Foundation/Localization` section) first — it sets the resolution mechanics for every locale but says nothing about Bulgarian register, only that "Romanian uses informal 'tu'" (line 43), so the `bg` address is an Open decision, not an inherited one; then Apple's Bulgarian wording for anything that mirrors or names iOS (Platform terms); then this brief. `glossary/bg.json` records the outcomes.
- Every row here is agent research, produced without any shipped Bulgarian copy and without a native source. Nothing was reviewed by a native speaker, a certified translator or the owner. Treat the whole file as a seed (`decided_by: "skill-seed-2026-09-16"` in `glossary/bg.json`) and get a native read before the pilot batch; an editor finding against any row is legitimate.
- Engineering flags that block a ship. None is a copy problem; each goes in the report, never into a string.
  1. `AppLanguage.supportedLanguageCodes` is `["en", "ro"]` (`Manifesting/Foundation/Localization/AppLanguage.swift:6`) and the project's `knownRegions` is `(en, ro, Base)` (`Manifesting.xcodeproj/project.pbxproj:6891-6895`), so `AppLanguage.setOverrideCode("bg")` is silently ignored (same file, lines 28-33) and the catalog would not compile a `bg.lproj` until both lists gain the code.
  2. The 25 shield pairs are not catalog strings: `ShieldMessage` carries fixed per-language fields `titleEnglish` / `titleRomanian` / `bodyEnglish` / `bodyRomanian`, and `title(languageCode:)` / `body(languageCode:)` return Romanian only for `"ro"` and English for everything else (`Manifesting/Foundation/ShieldSupport/ShieldMessage.swift:11-26`). A Bulgarian device gets English shields; shield copy is out of scope for `bg` until the struct becomes catalog-backed.
  3. App Store Connect offers no Bulgarian localization: Bulgarian is absent from both the help-page language list and the locale-shortcode table, and the Bulgaria storefront row reads `BGR | Bulgaria | English (U.K.) | ` (pages fetched 2026-09-16, `apple-coverage.json` `app_store_connect`). Store metadata for this audience ships in English (U.K.); `references/store-metadata.md` plans nothing for `bg`.
  4. Currency gap. `CurrencyCatalog` maps BG to EUR, but `AppCurrency.suggestedCode` reads `locale.currency?.identifier` and falls back to `"USD"` when the code is not in the catalog (`Manifesting/Foundation/Localization/AppCurrency.swift:19-22`); for `bg_BG` that identifier is **BGN** under CLDR 46.0.0.0 with both host ICU and the iOS 26.1 runtime's `icudt76l.dat`, and BGN is not among the catalog's 32 codes, so a fresh Bulgarian device starts at USD. Bulgaria adopted the euro on 1 January 2026 at the fixed rate EUR 1 = BGN 1.95583 (Council Decision (EU) 2025/1407 of 8 July 2025; https://trade.ec.europa.eu/access-to-markets/en/news/bulgaria-adopts-euro-1-january-2026, fetched 2026-09-16), so EUR is the right default and the OS locale datum is the stale side.
  5. Compact money suffixes are hard-coded Latin letters: `AppCurrency.formatCompact` picks `"k"`, `"m"`, `"b"` (`AppCurrency.swift:53-57`), so a Bulgarian reader sees `1,25k €` — Latin script inside Cyrillic copy — where the locale prints `1,25 хил. €`, `1,25 млн. €`, `1,25 млрд.` (`Decimal.FormatStyle.Currency(code:locale:).notation(.compactName)`, `bg_BG`; `locale-formats.json` `compact_finding`, severity medium). Copy cannot fix a code literal.
- Budgets: `references/surface-budgets.md`. There is no `references/examples-bg.md` yet; the skill seeds it from the first batch, and until then the translator and adjudicator use `examples-ro.md` as pattern illustration only (never the editor: its EN column breaks packet separation).

## Audience and register

- A friendly coach in everyday Bulgarian: short sentences, one idea per line, plain words a reader who knows no English understands at first read. The copy sits next to money and a timer, so dry warmth beats cleverness (`references/voice-card.md` `## Voice`).
- Prefer the naturalised everyday word over the calque and over the bureaucratic noun: "Статистика" for the Insights tab (`main.tab.insights`), not Apple's accessibility-framework phrase "Задълбочена информация" (21 characters, over the ~70pt tab-bar budget in `references/surface-budgets.md`); "цел" for a goal, not "таргет".
- Drop English scaffolding. 14 `en` units say "Please" (15 case-insensitively); Bulgarian app-owned copy says "моля" in none of them — the imperative carries the request. The `en` "Please try again." family (`currency.saveFailed`, `profile.name.saveFailed`, `quotes.user.saveError`, `moneyfesting.details.finalizeFailureAlertMessage` and the rest) becomes a bare "Опитай отново."

## Address and gender

- Apple's own register, from the harvest (iOS 26.1 (23B86)): body text is second person **plural** (Вие) with lowercase clitics — "Предоставянето на достъп на „%@“ до Екранно време може да позволи преглеждането на данните за активността **ви**…" (`Applications/FamilyControlsAuthenticationUI.app | Localizable.strings | NOTIFICATION_AUTH_REQUEST_MESSAGE_INDIVIDUAL`), "По-късно в приложението Здраве **можете** да включите…" (`System/Library/PrivateFrameworks/HealthUI.framework | HealthUI-Localizable.strings | AUTHORIZATION_DONT_ALLOW_ALERT_MESSAGE`) — while buttons are second person **singular** imperatives: Позволи, Не позволявай, Продължи, Запази, Включи, Започни, Добави, Пропусни (`UserNotificationsServer.framework | Localizable.strings | PERMISSION_ALERT_ALLOW`, `PERMISSION_ALERT_DENY`; `FamilyControlsAuthenticationUI.app | Localizable.strings | COMMON_CONTINUE`; `UIKitCore.framework | Localizable.strings | Save`; `SpringBoard.app | SpringBoard.strings | TURN_ON`). Motivational Apple copy uses the polite plural imperative: "Затворете вашите кръгове още три дни за голяма награда!" (`System/Library/Health/Assets/FitnessUIAssets.bundle/ActivityAchievements/365AllGoals/localization | Localizable-Modified-tinker.stringsdict | ACHIEVEMENT_UNACHIEVED_PROGRESS_THREE_AWAY_DESC/NSStringLocalizedFormatKey`).
- Formality is a genuine product choice for this app and is Open decision `formality`. **Meanwhile rule:** app-owned copy uses informal `ти` with second-person-singular imperatives on controls, matching Apple's own button person and the `ro` precedent in app `CLAUDE.md:43`; every string that quotes an iOS label or mirrors an iOS alert follows the device instead and keeps Apple's plural body text verbatim (Platform terms).
- Capitalisation of the polite forms: in a user interface they are **lowercase** (`ви`, `вашето`, `можете`). Two sources agree — Apple's Bulgarian UI writes them lowercase throughout the harvested strings, and the Bulgarian software/UI convention is stated explicitly for "брошури, наръчници, плакати, маркетингови материали, софтуер и потребителски интерфейс" (https://my.oltrans.bg/stilistichni-ukazaniya-na-oltrans-pri-prevod-na-ofitsialni-dokumenti-ot-chuzhd-ezik-na-balgarski-ezik/, fetched 2026-09-16) — against the general orthographic rule that the polite pronoun is capitalised (Institute for Bulgarian Language, BAS: "В състава на учтивата форма личното местоимение *вие* се пише с главна буква – *Вие*", https://ibl.bas.bg/ezikovispravki/vaprosi/mestoimeniya-i-imena-pri-izrazyavane-na-uchtivost-4/71, fetched 2026-09-16). See Decided conflicts.
- The app speaks about itself in the first person plural in dialogs and failures (19 `en` units: "We couldn't save your session changes.", `moneyfesting.details.finalizeFailureAlertMessage`; "We covered %@ with a streak freeze.", `streakFreeze.usedBody`). Bulgarian keeps that: "Не успяхме да…", "Покрихме %@ със замразяване на серия."
- **Gender is where Bulgarian and the formality choice meet.** Bulgarian marks gender on the *l*-participle (perfect tense) and on predicate adjectives and role nouns, but only in the singular: in the plural — which is what the polite `Вие` takes — the participle is the common form `-ли` and carries no gender. Apple's own copy shows it: "колко време **сте прекарали**", "кои приложения и уеб сайтове **сте използвали**" (`System/Library/PrivateFrameworks/ScreenTimeSettingsUI.framework | Localizable.strings | WeeklyReportNotificationGroupSpecifierFooterText`). So `Вие` makes reader-directed participles neutral for free, and `ти` forces a gender choice on every one of them. Weigh that in Open decision `formality`.
- Neutral strategies under `ти`, in order of preference:
  1. **Aorist instead of the perfect.** The simple past is not gendered: "Появи се 5 дни подред." and "Фокусира се %lld от 7 дни." carry no gender, where "Ти си се появил/появила" does. Governs `achievements.streak.body` (en "You showed up %lld days in a row."), `achievements.streak.weekAccessibility` (en "You focused %lld of 7 days."), `achievements.badge.rehired.earned` (en "A week away, and you're back.").
  2. **Imperatives**, which are never gendered: "Фокусирай се два дни подред." (`achievements.badge.dayTwo.criterion`), "Започни следващата." (`widgets.streak.copy.lapsed`).
  3. **Nominal sentences** with no verb aimed at the reader: "Седем дни подред. Без пропуск." (`achievements.badge.hired.earned`, en "Seven days, no gaps."), "Един цял час, без прекъсване." (`achievements.badge.longShift.*`).
  4. **Agreement with the object, not the reader**: "%lld избрани" agrees with "теми", not with the user (`themePicker.manageThemes.selectedCount`); "%lld блокирани приложения" agrees with "приложения" (`screenTime.restrictedApps.appsRestricted`; word choice "блокирани", not "ограничени" — glossary `restricted_list`, Decided conflicts).
  5. Avoid predicate adjectives aimed at the reader ("готов/готова", "сигурен/сигурна"): `screenTime.createRestrictedList.savedMessage` (en "when you're ready"), `focusTask.alert.deleteTask.message` (en "Are you sure…"), `shield.reflection.begin.title` (en "Begin before you're ready.") all invite one; rewrite as a nominal or an aorist.
- Where no neutral form exists, ship the **masculine singular** and record the key in the batch report so the owner sees the list. The hotspot is the badge workplace conceit, which is role nouns by design: `achievements.badge.hired.name` (Hired), `salaried.name` (Salaried), `rehired.name` (Rehired), `permanent.name` (Permanent), `backOnShift.name` (Back on shift) — 24 `achievements.badge.*.name` keys in all. Nominal rewrites exist for several ("Нает" -> "Първи работен ден"; "На заплата" is invariant and already neutral), but the metaphor is a product choice, so propose, never decide (Open decisions in `references/locale-briefs/ro.md` set the precedent). `user.gender.other` ("Other") takes the neuter "Друго", which is neutral in form.
- Grep aid, not a validator: `нает | наета | готов | готова | сигурен | сигурна | фокусиран | фокусирана | доволен | доволна`, plus the *l*-participle shape `\w+(ал|ала|ил|ила|ел|ела)\b` — which also hits third-person narrative and the word "дела", so read every hit.
- The stored profile gender (`Manifesting/Features/User/Domain/Entities/Gender.swift`) is not a copy input without a product decision.

## Control forms

Counts are `en` keys whose value is exactly the control word, the match `scripts/term_audit.py` makes; there is no `bg` split to report. Preferred and role forms mirror `glossary/bg.json` `controls` exactly, because the script reads the glossary, not this table.

**The local convention is per control, not one mood.** Bulgarian iOS does not use a single button form: action buttons are second-person-singular imperatives (Позволи, Не позволявай, Продължи, Запази, Пропусни, Включи, Започни, Добави, Затвори, Опитай пак, Отвори Настройки, Редактирай), while two standard bar and alert controls keep a verbal noun (Отказ for Cancel, Изтриване for Delete), and one link-style action keeps the polite plural (Научете повече for Learn More). Edit is *not* a third verbal-noun control: `UIKitCore.framework | Localizable.strings | Edit` renders the outlier "Редакция" in exactly one iOS 26.1 runtime string, while every other Edit/EDIT key in the same runtime (AssistiveTouch, VoiceOverTouch, every Health FeedItemPlugin, every AccessibilityBundle, GameCenter, Preferences.framework, UIKitCore's own MACMENUBAR_EDIT) renders the imperative "Редактирай" — the form a Bulgarian reader parses as an action on a real button such as `common.edit`/`insights.mood.edit`, unlike "Редакция", which reads as "editorial office/edition." Evidence, all iOS 26.1 (23B86): `UIKitCore.framework | Localizable.strings | Cancel`, `Delete`, `Save`, `Continue`, `Close`; `UserNotificationsServer.framework | Localizable.strings | PERMISSION_ALERT_ALLOW`, `PERMISSION_ALERT_DENY`; `SpringBoard.app | SpringBoard.strings | TURN_ON`, `FACE_ID_DISABLED_GO_TO_SETTINGS`; `Health/FeedItemPlugins/MenstrualCyclesAppPlugin.healthplugin | Localizable.strings | ONBOARDING_SKIP`; `EscrowSecurityAlert.app | Localizable.strings | LEARNMORE`. ## Header and label forms

- Sentence case for app-owned copy, with feature and product names capitalised inside the sentence — Apple's own pattern: "Редактирай Начален екран" (`SpringBoardHome.framework | SpringBoardHome.strings | REARRANGE_ICONS_SHORTCUT_ITEM_TITLE`), "По-късно в приложението Здраве можете да включите категориите здравни данни." (`HealthUI.framework | HealthUI-Localizable.strings | AUTHORIZATION_DONT_ALLOW_ALERT_MESSAGE`). The 114 Title Case `en` keys lose the extra capitals.
- Screen titles are nominal, even where `en` uses a Title Case imperative: "Set Your Hourly Wage" (`onboarding.hourlyWage.title`) becomes "Часова ставка", not a conjugated sentence; buttons keep the imperative. All 8 `.navigationTitle` sites are `.inline`, so the title competes with about 176pt of bar items (`references/surface-budgets.md`).
- Eyebrows and stat captions are uppercase in the string wherever `en` is uppercase (34 all-caps `en` keys). Bulgarian uppercasing is a plain one-to-one Cyrillic map — no dotted/dotless i, no ß, no accents to strip — and Apple uppercases Cyrillic straight through: "ИЗВЕСТИЯ", "КАЛЕНДАРИ", "ВРЪЩАНЕ КЪМ ЧАСОВНИК", "КИТКАТА Е НАДОЛУ" (`System/Library/BridgeManifests/BridgeManifests.bundle | SettingsSearchManifest-com.apple.NanoCalendarBridgeSettings.strings | NOTIFICATIONS`, `CALENDARS`; `SettingsSearchManifest-com.apple.internal.CompanionReturnToClockSettings.strings | RETURN_TO_CLOCK`; `SettingsSearchManifest-com.apple.Bridge.strings | WRIST_DOWN`). The one trap is the abbreviation full stop, which survives uppercasing and must be kept: "мин" -> "МИН", "прибл." -> "ПРИБЛ.", "г." -> "Г.". Seeded eyebrows: MOOD -> НАСТРОЕНИЕ, DAY STREAK -> ДНИ В СЕРИЯ, TODAY -> ДНЕС, LAST 30 DAYS -> ПОСЛЕДНИТЕ 30 ДНИ, TASKS DONE -> ЗАВЪРШЕНИ ЗАДАЧИ, EST. TIME VALUE -> ПРИБЛ. СТОЙНОСТ НА ВРЕМЕТО (26 characters against 15 in `en`, the hardest expansion on the Insights summary card, `insights.summary.moneyfestingTitle`), "%@ / HOUR" -> "%@ / ЧАС" (`onboarding.hourlyWage.unit`, `profile.hourlyWage.unit`).
- Section headers are plural participles or adjectives agreeing with the listed items: ПЛАНИРАНИ, ЗАВЪРШЕНИ, ПО ВСЯКО ВРЕМЕ (`plan.dailyPlan.plannedHeader`, `doneHeader`, `anytimeHeader`), "Завършени днес" (`onboarding.welcome.preview.ring.completed`), "Получени наскоро" (`achievements.gallery.recentSection`, agreeing with the badges listed under it, not with the reader).
- Tab titles are bare nouns with no article: Moneyfesting, План, Статистика, Профил (`main.tab.*`), about 70pt each at 10pt with no scaling.
- Toggles and state labels take a participle or adjective agreeing with the labelled noun: "Избраните приложения са блокирани"; "%lld блокирано приложение" / "%lld блокирани приложения" (`screenTime.restrictedApps.appsRestricted` — "блокирани", matching `screenTime.createRestrictedList.*` and the glossary's `restricted_list`, not the en source's own "restricted"; see Decided conflicts); "Фокусът е на пауза" (`widgets.startFocus.paused`). A fragment with no visible noun agrees with the noun the screen implies, and the packet names it in `agreement_target`: `widgets.streak.copy.frozen.small` ("Covered by a freeze.") sits beside a day, so it is masculine "Покрит със замразяване.", not neuter "Покрито" — the agreement fault the editor checks.
- Status pills that describe the action rather than the reader default to the neuter singular: "Запазено" for `common.editor.saved`.
- The definite article is the standing Bulgarian error in UI fragments. A label with no verb takes the **indefinite** form ("План", "Часова ставка", "Серия"), not the article ("Планът"); the full masculine article `-ът/-ят` belongs to a grammatical subject ("Планът е готов") and the short `-а/-я` to an object or a prepositional phrase ("в Началния екран" as a prepositional phrase; "Отвори Профила" as a plain object). "Настройки" takes the separate plural-definite suffix `-те` ("Настройките") regardless of gender — a different paradigm, not an instance of `-а/-я`, so it is not a substitute example for the masculine-object case. Grep aid, not a validator: a label ending in `ът|ят|та|то|те` with no verb in the string.

## Numbers, dates, currency and punctuation

All runtime values arrive formatted through `AppLanguage.effectiveLocale` (app `CLAUDE.md`), so no string hard-codes a decimal, a separator or a currency; every sample below is Foundation/ICU output for `bg_BG` recorded in `locale-formats.json` (ICU 76.1.0.0, CLDR 46.0.0.0, iOS 26.1 runtime data).

- Decimal separator is the comma (U+002C); the grouping separator is a **no-break space** (U+00A0). Four-digit numbers are not grouped: `2000` stays "2000" while `12000` is "12 000" and `1250000` is "1 250 000". A literal number written into copy follows the same rule ("2000 часа" for `achievements.badge.wageYear.*`, en "2,000 hours of focus").
- Money: the app's narrow presentation gives "120 €" and "1250,5 €", the locale standard "120,00 €"; the symbol follows the number after U+00A0. The compact form the app builds is "1,25k €" and must be reported, not rewritten (Identity, flag 5); the locale's own compact tokens are "хил.", "млн.", "млрд.".
- Percent is glued to the number with no space: "40%", "100%" (U+0025 after the digits), so `-%lld%%` and `%lld%% OFF` keep their shape.
- Time is 24-hour (`Locale.hourCycle` h23, `DateFormatter` template `j` -> `H`): "23:59", "9:41" with no leading zero on the hour. Axis labels become 00:00 / 06:00 / 12:00 / 18:00 (`insights.appUsage.axis*`, `profile.appUsage.axis.*`, `screenTimeReport.axis*`).
- Dates: numeric "31.12.2026 г." with a **narrow no-break space** (U+202F) before "г."; wide "31 декември 2026 г."; day and month "12 май"; weekday "вторник", "вторник, 12.05". Never drop the "г." and never replace the U+202F with a normal space.
- Quote marks are „ (U+201E) opening and “ (U+201C) closing — both the primary and the alternate pair — so `„%@“`, not `„%@”` (Romanian) and not `"%@"`. This governs `moneyfesting.details.quoteWrapper`, `notifications.contentExtension.quoteDecoration`, `moneyfesting.main.quotePlaceholder`, `theme.createTheme.sampleQuote`, `widgets.quotes.placeholderText`, the two mock alert titles, and every UI label quoted inside a sentence ("Натисни „Опитай отново“", `component.errorView.message`). Apple writes the same pair: „%@“ иска достъп до Екранно време (`FamilyControlsAuthenticationUI.app | Localizable.strings | NOTIFICATION_AUTH_REQUEST_TITLE`).
- Ranges take an en dash with no spaces ("1–3 часа", "18–24"); asides take a spaced em dash, mirroring the 2 `en` em-dash keys; the ellipsis is three periods, following the `en` catalog's own majority (9 keys with "..." against 2 with "…"). Multiplication uses × ("Часовете ти на фокус × часовата ти ставка", `achievements.category.wages.description`). These three are seed conventions with no ICU datum behind them; an editor finding beats them.
- Plural categories are **one** and **other** — the same two `en` has, and two fewer than Romanian (`variationConfigFile.plist` `PluralRule.ComplementedPluralKeys.bg`; ICU keyword probe). Only `1` selects `one`; `0`, `2`, `3`, `5`, `11`, `20`, `21`, `100`, `101`, `1000`, `1000000` and every fraction tested (0.5, 1.5, 2.5) select `other`. Exercise **0, 1, 2, 5, 11, 21, 101 and 1.5**: the two surprises are that 0 is `other` and that 1.5 is `other` while 1 is `one`. Because `en` and `bg` share the category set, the 29 `en` plural keys map one to one — but the 6 keys that are plural in `ro` only and a single `stringUnit` in `en` still need a `bg` split, since 1 takes its own form (`achievements.streak.body`, `comebackBody`, `headline`, `milestoneBody`, `nextMilestoneBody`, `weekAccessibility`).
- Numerals attach to nouns through the **count form** (бройна форма) for masculine non-person nouns: after a numeral, `час` becomes "часа" and not "часове", `ден` becomes "дни", `път` becomes "пъти". The rule is that only masculine nouns for non-persons take it, after cardinal numerals and quantity words (Institute for Bulgarian Language, BAS: "бройна форма имат само съществителните имена от мъжки род за нелица", https://ibl.bas.bg/pishi_pravilno/greshki-pri-upotrebata-na-broynata-forma/, fetched 2026-09-16), and Apple's own strings follow it: `%d час` / `%d часа`, `%d ден` / `%d дни`, `%d път` / `%d пъти` (`VoiceOverTouch.app | VOTLocalizedStrings.stringsdict | hours.format/hours/one` and `/other`; `Health/FeedItemPlugins/Heart.healthplugin | BloodPressureJournal-Localizable.stringsdict | PDF_CLASSIFICATION_COUNT/value/one` and `/other`; `PreferenceBundles/Privacy/HealthPrivacySettings.bundle | Localizable.stringsdict | EXPOSURE_FOOTER_APP_INFO_%@_%d_%@/checkstoday/one` and `/other`). Feminine and neuter nouns just take the plural: `%d минута` / `%d минути`, `%d приложение` / `%d приложения`, `%d категория` / `%d категории` (`VoiceOverTouch.app | VOTLocalizedStrings.stringsdict | hours.minutes.format/minutes/one` and `/other`; `ScreenTimeSettingsUI.framework | Localizable.stringsdict | NumberOfAppsFormat/apps/one` and `/other`). Unlike Romanian there is **no** linking word before the noun at any magnitude: "20 дни", "60 минути", "160 часа".

## Length trigger

- A Bulgarian string longer than **1.35×** its `en` length goes on the render list; `scripts/catalog_check.py` C5 puts it there, not among findings. The ratio comes from Apple's own Bulgarian translations: across 47 810 unique English/Bulgarian pairs from 1 269 iOS 26.1 (23B86) UI bundles, 28.4% exceed 1.35×, which is the rounded ratio at which Apple's `bg` behaves like Apple's `ro` at the same threshold (31.6%, the Apple statistic closest to the `ro` catalog's 299 of 1135, 26.3%) — `length-stats.json` `recommendation`.
- Where it will bite: short strings. 36.6% of Apple's 1–10 character pairs exceed 1.35× with a p90 of 2.0×, against 13.7% and p90 1.39× for 41–120 character pairs. All-caps strings are gentler than in Romanian (26.2% above 1.35×, median 1.0×, p90 1.8×), but the long captions still blow up: EST. TIME VALUE -> ПРИБЛ. СТОЙНОСТ НА ВРЕМЕТО is 1.73×, DAY STREAK -> ДНИ В СЕРИЯ 1.2×, Done -> Готово 1.5×, Skip -> Пропусни 2.0×.
- There is no `bg` catalog share to quote: 0 of 1189 keys carry a Bulgarian unit. Counts never establish fit anyway; verdicts come from render evidence against each view's own floor and cap (`references/surface-budgets.md`, `references/render-evidence.md`). Shortening cuts words, never facts; accessibility strings are exempt.

## Open decisions

Each item is mirrored in `glossary/bg.json` `open` with the fields `scripts/term_audit.py` reads. Nothing is translated yet, so "meanwhile" means: the rule a translator follows on the first batch, and the adjudicator lists every key that touched the term.

- **Formality (`formality`).** Affects every reader-directed string in the catalog — roughly the 177 second-person possessive units, the 12 control labels and all onboarding and celebration copy. Rule: app-owned copy uses one address, and any string mirroring iOS follows the device. Options: **ти** (second person singular, 2sg imperatives on controls) — evidence: every Apple Bulgarian button is a 2sg imperative (Позволи, Продължи, Запази, Пропусни, Включи), the app's voice card asks for a friendly coach, and app `CLAUDE.md:43` chose informal for the one locale it names; **Вие** (polite plural, lowercase clitics) — evidence: all Apple Bulgarian *body* text uses it, including motivational Fitness copy ("Затворете вашите кръгове…"), and it makes every reader-directed participle gender-neutral for free, which removes the whole gender problem in Address and gender. Recommended: **ти**, because the app's controls, celebrations and widget lines are short second-person lines where the polite plural reads like a bank, and Apple's own buttons are already 2sg. Meanwhile: translate with `ти`, keep every iOS mirror in Apple's plural, and record in the report every key where `ти` forced a gendered participle or adjective, so a flip to `Вие` has its list ready. No fetched source establishes a Bulgarian consumer-app norm either way; a native read should settle this before the pilot batch.
- **Focus term (`focus_session`).** Affects `widgets.startFocus.heading` ("Focus session"), `profile.sessionDetails.*`, `moneyfesting.details.*`, `onboarding.welcome.preview.blocking.*`, `profile.home.focusSection` (en "Focus"), `widgets.focusRing.*`. Rule: one target term for the app's own focus concept, chosen once and applied everywhere. Options: **сесия за фокус** — evidence: "фокус" is the fully naturalised Bulgarian noun and Apple's own name for the system mode (`Applications/Preferences.app | Localizable.strings | Focus` -> "Фокус"), and it is short, which matters at 1.35× on widget lines; **сесия за концентрация** — evidence: "концентрация" is unambiguous and cannot be read as the iOS Focus mode, but it is 12 characters against 5 and would push `widgets.startFocus.heading` past the Start Focus capsule budget (about 118pt of text, `references/surface-budgets.md`). Recommended: **сесия за фокус**, because `en` already shares the word "Focus" with the iOS mode and accepted the overlap, and Bulgarian would pay for avoiding it in width on exactly the surfaces that have none to spare. Meanwhile: use "фокус" and its verb "фокусирам се" for the app concept, never for the system mode, and list every key that touched the term.
- **Forecast label (`forecast`).** Affects `insights.savings.forecast` (en "Forecast") beside `insights.savings.monthEnd`, plus the three estimate explanations (`estimateExplanation`, `measuredEstimateExplanation`, `focusHistoryEstimateExplanation`) and `insights.appUsage.permissionDescription`. Rule: VoiceOver reads the forecast line and the month-end figure one after the other, so they need two different words. Options: **Прогноза** — the everyday word for a forecast, leaving "Оценка"/"приблизителна стойност" free for the month-end figure; **Оценка** — closer to "estimate", but then both lines carry the same word; **Проекция** — a calque that reads technical. Recommended: **Прогноза**, because it is the only one of the three that keeps the two adjacent labels distinct without borrowing the sanctioned "estimated" family the Money frame already spends on the disclaimers. Meanwhile: "Прогноза" on the forecast line, "Оценка към края на месеца" on the month-end figure, and never the same word twice on that card.
- **Widget noun in app-owned copy (`widget_noun`).** Affects the app's own widget copy: `onboarding.widgets.howTo.chooseTitle`, `editTitle`, `subtitle`, `step4`, `onboarding.widgets.intro.appIconInstruction`, `onboarding.welcome.preview.streak.homeScreen`, `onboarding.welcome.slide.streak.eyebrow`, `profile.home.widgetsRow` and the widget gallery display names. The mirrors are not in scope: they must say Apple's word. Rule: app-owned copy names an Apple feature the way the device does. Options: **инструмент** — evidence: Apple translates the noun in every Bulgarian Home Screen string ("Добави инструмент", "Премахни инструмент", "Търси инструменти", "Премахването на този инструмент няма да изтрие приложения или данни."), so this is the word on the reader's own screen; **уиджет** — evidence: the transliteration is what Bulgarian speakers say out loud, and Apple itself keeps the loanword in other locales' plural forms, but no bg iPhone screen shows it. Recommended: **инструмент**, because the how-to screen's whole job is to walk the reader through menus that say "инструмент", and a tutorial that names the thing differently from the menu it points at is a tutorial that fails. Meanwhile: use "инструмент" everywhere, mirrors included, and record any string where "инструмент" reads as a generic tool rather than the feature.
- **Edit pill label (`edit_pill_label`).** Affects `onboarding.widgets.howTo.editPillLabel`, drawn on the illustrated iOS Edit pill (`Manifesting/Features/Onboarding/Business/WidgetsHowTo/View/HomeScreenJiggleIllustrationView.swift:151`), and `step2`, which quotes it. Rule: an illustrated iOS label mirrors the device verbatim. Options: **+** — evidence: Apple's Bulgarian value for that entry is the literal "+" (`SpringBoardHome.framework | SpringBoardHome.strings | EDIT`, the same choice Apple makes in fi, hu, tr and fr), which is what the reader's Home Screen actually shows; **Редакция** — evidence: UIKit's generic Bulgarian Edit label, a word that fills the drawn pill the way the `en` and `ro` values do, but a word no Bulgarian Home Screen displays. Recommended: **+**, because the row resolves against the device language precisely so it reads like the user's own screen, and a label the device never shows sends the reader looking for a button that is not there. A yes needs a render check of the pill and of `step2` ("Натисни + в горния ъгъл, после Добави инструмент."), where a bare "+" mid-sentence may need quoting as „+“. Meanwhile: mirror "+" and raise the render question in the batch report.
