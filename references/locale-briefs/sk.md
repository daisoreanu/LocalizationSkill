## Identity

- Tag `sk`, the bare code. `sk-SK` negotiates to `sk` in both the v1 and the wave-2 language lists, iOS ships only `sk.lproj` (no `sk_SK.lproj` exists in the runtime), and `xcstringstool` compiles `sk.lproj`; Xcode's `LOCLocaleCode.plist` lists `sk` with display name "Slovakian" and lproj `sk`.
- Audience: Slovak speakers in Slovakia on an iPhone set to Slovak. Latin script with diacritics (á ä č ď é í ĺ ľ ň ó ô ŕ š ť ú ý ž), left to right. Format locale `sk_SK`, audience currency EUR.
- Snapshot 2026-09-16 against catalog commit c8a49dd: **0 `sk` units in the catalog**. The catalog holds 1189 keys with `en` on 1142 and `ro` on 1135; there is no Slovak copy to count, to align against, or to cite as a majority.
- Precedence: app `CLAUDE.md` (`:42` — the resource locale selects the translation and the plural rules; `:43` carries a Romanian line only, so nothing there binds Slovak), then Apple's Slovak wording for anything that mirrors or names iOS (`## Platform terms`), then this brief. `glossary/sk.json` records the outcomes.
- **This whole brief is agent research.** No Slovak copy has shipped, no native speaker and no certified translator has read any line of it, and the owner has accepted none of it. Every target string below is an agent-authored illustration, not shipped copy. A native read of the hero set, the shield pairs and the store text is recommended before the pilot batch, and `SKILL.md` `## Verify and deliver` already requires it on a locale's first ship.
- Tone examples: none yet — the first batch returns six rows in the `references/examples-ro.md` format, which the coordinator saves as `references/examples-sk.md`. Budgets: `references/surface-budgets.md`.

## Audience and register

- The app talks to a Slovak reader the way a calm colleague would: everyday words, one idea per line, short sentences, no IT jargon, and no sentence a reader without English has to decode. Microsoft's Slovak style guidance says the same in its own words — "The general style should be clear, friendly and concise. Use language that resembles conversation observed in everyday settings" and "being friendly does not mean using overly colloquial language; always maintain a professional tone" (Microsoft Slovak Localization Style Guide, `download.microsoft.com/.../slk-svk-StyleGuide.pdf` §2.1, fetched 2026-09-16). It also warns that Slovak keeps a wide gap between official and colloquial registers and that readers are conservative about product language (§4.1.10), which is why the coach voice lands on plain and warm rather than chatty.
- Apple's Slovak is the neighbour this copy sits beside: sentence case, `vy`, infinitive buttons, and the short noun `apka` for an app in most strings (`System/Library/PrivateFrameworks/UserNotificationsServer.framework | Localizable.strings | USER_NOTIFICATION_PERMISSION_ALERT_TITLE` "Apka %@ vám chce posielať hlásenia").
- Drop English scaffolding. 15 `en` keys carry "please" (14 capitalised); Slovak error copy does not need "Prosím" and the request is already in the verb.
- Imported shapes the editor flags. The first two columns are the marker list the coordinator appends to the editor prompt, target text only; the key column stays coordinator-side (`references/agent-protocol.md` `## Packet separation`). **Every target string in this table is an agent-authored illustration** — there is no Slovak copy to quote.

## Address and gender

- **Pronoun: `vy` (vykanie), one form everywhere.** Apple's Slovak addresses a single iPhone owner with the second-person plural throughout: "Apka %@ vám chce posielať hlásenia" (`UserNotificationsServer.framework | Localizable.strings | USER_NOTIFICATION_PERMISSION_ALERT_TITLE`), "Keď apke „%@“ poskytnete prístup … s vašimi aktivitami" (`Applications/FamilyControlsAuthenticationUI.app | Localizable.strings | NOTIFICATION_AUTH_REQUEST_MESSAGE_INDIVIDUAL`), "Kategórie zdravotných dát môžete neskôr zapnúť v apke Zdravie" (`HealthUI.framework | HealthUI-Localizable.strings | AUTHORIZATION_DONT_ALLOW_ALERT_MESSAGE`). Apple ships `ty` only in the Fitness "tinker" string variants written for a teenage Activity audience (`FitnessUIAssets.bundle/.../Localizable-Modified-tinker.stringsdict`), never in system UI. This is a product choice the owner has to make, because `en` and `ro` are both informal — Open decision `address_formality`; until it is closed, agents write `vy`.
- **`vy` is also the gender strategy.** The Slovak *l*-participle has three singular forms (`urobil` / `urobila` / `urobilo`) but **one plural form for every gender** (`urobili`), so a plural-addressed past tense never states the reader's gender. Apple's own pair proves it: the same award line is "Toto ocenenie **ste získali** za svoj prvý tanečný tréning." with `vy` (`FitnessUIAssets.bundle/ActivityAchievements/FirstWorkout-HKWorkoutActivityTypeCardioDance/localization | Localizable.stringsdict | ACHIEVEMENT_ACHIEVED_DESCRIPTION`) and "Toto ocenenie **máš** za to, že **sa ti podarilo** zabehnúť 5 kilometrov." with `ty` (`.../FiveKilometerWorkout/localization | Localizable-Modified-tinker.stringsdict | ACHIEVEMENT_ACHIEVED_DESCRIPTION`) — the `ty` version has to reach for the impersonal "podarilo sa ti" precisely because a direct singular past tense would have to pick a gender. Choosing `ty` therefore costs a rewrite of every reader-directed past-tense line.
- Neutral strategies Slovak offers, in the order an agent should try them:
  1. **`vy` plural past** for anything the reader did: "Uzatvorili ste všetky kruhy" (`FitnessUIAssets.bundle/ActivityAchievements/365AllGoals/localization | Localizable.stringsdict | ACHIEVEMENT_ACHIEVED_ALERT_DESCRIPTION`). Hotspots: `achievements.streak.body` ("You showed up %lld days in a row."), `achievements.streak.weekAccessibility`, `achievements.badge.rehired.earned` ("A week away, and you're back."), `achievements.badge.hired.earned`, `achievements.badge.fullDaysFifty.earned`.
  2. **Plural imperative** for instructions: "Klepnite na Upraviť." Hotspots: `achievements.badge.dayTwo.criterion`, `achievements.badge.salaried.criterion`, the five `onboarding.widgets.howTo.step*` keys.
  3. **Nominal sentences and verbal nouns** where an achievement is being named rather than the reader described: "Sedem dní bez prestávky." Hotspots: the 24 `achievements.badge.*.name` keys and the 5 `achievements.category.*.name` keys.
  4. **Agreement with the object, not the reader**, for counts and states: "%lld vybraté" agrees with "témy" (f. pl.), not with the user. Hotspots: `themePicker.manageThemes.selectedCount`, `profile.home.quoteCategoriesRow.count`, `screenTime.restrictedApps.appsRestricted`, `component.editableCard.selected`.
  5. **Role nouns rewritten as noun phrases.** This is the one real pressure point: the badge family is built from job titles (`achievements.badge.hired.name` "Hired", `.salaried.name` "Salaried", `.rehired.name` "Rehired", `.clockedIn.name` "Clocked in", `.permanent.name` "Permanent", `.tenure.name` "Tenure"), and a Slovak adjective aimed at the reader must pick a gender ("Prijatý"/"Prijatá"). Slovak lets every one of them become a neutral noun phrase that agrees with its own head noun instead: "Nástup" (Hired), "Na výplatnej páske" (Salaried), "Návrat do práce" (Rehired), "Pichnutá karta" (Clocked in, agreeing with *karta*), "Trvalý pracovný pomer" (Permanent, agreeing with *pomer*), "Odpracované roky" (Tenure). Agent-authored illustrations; the strategy is the rule, the wording is a proposal. Flag, not decided here: "Na výplatnej páske" (a prepositional phrase) and "Pichnutá karta" (a physical object standing in for the action) do not share the short deverbal/state-noun shape of the other four; reconcile the set to one shape before it ships. Separately, "Pichnutá karta" (short i, from *pichnúť*, a one-time action — matching a single card punch) against "Píchnutá karta" (long í, from *píchať*) has no Apple evidence either way; a native check is recommended before the spelling ships.
- **Shipped default where no neutral form exists:** there is none yet, because nothing has shipped. The rule for the first batch is that a reader-directed predicate adjective or role noun is a finding, not a choice: rewrite it with strategy 1–5 above. If a specific string genuinely resists all five, the translator flags it and the coordinator records the masculine default in this section with the key it touches, rather than the translator picking silently. `user.gender.*` (`Female` / `Male` / `Other` / `Prefer not to say`) are picker values about the reader's own stated gender and take the plain nouns; the stored profile gender (`Manifesting/Features/User/Domain/Entities/Gender.swift`) is not a copy input without a product decision.
- Grep aid, not a validator: a target unit matching `\b\w+(ý|á|é|í)\b` next to `ste`, or any of `prijatý|prijatá|zamestnaný|zamestnaná|pripravený|pripravená|sústredený|sústredená|istý|istá`, is a reader-directed adjective to check against the packet's `agreement_target`.
- The app also speaks in the first person plural in dialogs and states — 19 `en` units, "We couldn't load the data.", "We covered %@ with a streak freeze.", "We'll try again soon." Slovak keeps that: "Dáta sa nám nepodarilo načítať.", "Skúsime to znova." Apple does the same on a Screen Time footer ("upozorníme vás na to", `ScreenTimeSettingsUI.framework | Localizable.strings | WeeklyReportNotificationGroupSpecifierFooterText`).

## Control forms

**The local convention is the infinitive, not the bare imperative.** Two independent sources agree: Microsoft's Slovak style guide states it as a rule — "The basic verbal form is the infinitive. Other forms (verbal nouns, participles, etc.) are only permissible in cases in which an infinitive cannot be formed. Names of buttons should not end with any kind of punctuation mark." (§5.5.2, fetched 2026-09-16) — and every generic iOS control is an infinitive in Slovak: Zrušiť, Uložiť, Upraviť, Vymazať, Zatvoriť, Pokračovať, Povoliť, Nepovoliť (`UIKitCore.framework | Localizable.strings | Cancel, Save, Edit, Delete, Close, Continue, PASTE_ALLOW_BUTTON_TEXT, Don't Allow`). Romanian's bare imperative is **not** carried over; it has no evidence in Slovak. Two named exceptions, both Apple's own: `Hotovo` for Done (an adverb, no infinitive exists) and `Rozumiem` for Got it (first person singular).

There is no Slovak catalog, so the count column is the number of `en` keys whose value equals the control label under `scripts/term_audit.py`'s rule (`en.strip().rstrip("…").strip().casefold() == label.casefold()`) — the keys the row will govern. ## Header and label forms

- **Sentence case for everything the app owns.** Microsoft's Slovak guide: "Translators should use capital starting letter only in cases word/phrase/expression is a title, product name, feature name or a proper name" (§4.1.6, fetched 2026-09-16); Apple's Slovak register summary from the same harvest is "sentence case". The 114 Title Case `en` strings of two to four words lose their capitals: `focusTask.picker.templatesHeader` "Task Templates" -> "Šablóny úloh", `profile.sessionDetails.allTimeTitle` "All Time" -> "Za celý čas".
- **Screen and dialog titles built on a verb take a verbal noun, not the infinitive.** Microsoft §5.5.3: "If a verb is used in the original (such as Confirm something, Select something, etc.), use a verbal noun in the translation" — "Select Device" -> "Výber zariadenia", "Confirm File Rename" -> "Potvrdenie premenovania súboru". So `focusTask.createTask.screenTitleEdit` "Edit Focus Task" -> "Úprava úlohy sústredenia" and `screenTime.createRestrictedList.screenTitle` "Create Restricted List" -> "Vytvorenie zoznamu blokovaných apiek", while the *button* that performs the same action keeps the infinitive. This split is the single most common place a Slovak reader notices a translated app.
- **All-caps eyebrows and captions stay all-caps when the source is** (34 `en` strings have no lower-case letter): MOOD -> NÁLADA, DAY STREAK -> DNI V SÉRII, TASKS DONE -> HOTOVÉ ÚLOHY, TODAY -> DNES, LAST 30 DAYS -> POSLEDNÝCH 30 DNÍ, EST. TIME VALUE -> ODHAD. HODNOTA ČASU, TODAY'S FOCUS -> DNEŠNÉ SÚSTREDENIE, "%@ / HOUR" -> "%@ / HOD.". Microsoft §4.1.6 allows exactly this: "In case there is some specific reason (e.g. graphical) localized string/word/phrase can follow English source all caps or no caps style."
- **Uppercase keeps every diacritic, including the caron on ľ ď ť.** Apple's own all-caps Slovak: ZDIEĽANÉ SO SKUPINOU (`SafetyMonitorMessages.bundle | Localizable.strings | SHARED WITH GROUP`), CIEĽ (`| DESTINATION`), OTVORIŤ (`AcousticId.siriUIBundle | Localizable.strings | OPEN`), HLÁSENIA, SKÚSIŤ ZDARMA (`AppStoreKit.framework | Localizable.strings | INTRO_PRICE_OFFER_FREE_TRIAL`). Slovak has no ß and no dotted/dotless i, so nothing here needs a special-casing rule; the one thing to watch is the digraph `ch`, which uppercases as `CH` (both letters) inside an all-caps string.
- Tab titles are nouns: Moneyfesting, Plán, Prehľady, Profil (`main.tab.*`; Apple's Insights is "Prehľady", `AccessibilitySharedUISupport.framework | AccessibilitySharedUISupport.strings | Insights`).

## Numbers, dates, currency and punctuation

All values below are Foundation/ICU output for `sk_SK` captured on 2026-09-16 unless another source is named; runtime values reach the UI already formatted through `AppLanguage.effectiveLocale` (app `CLAUDE.md:42`), so no string hard-codes a separator or a currency.

- **Decimal separator is the comma** (U+002C); **grouping separator is a no-break space** (U+00A0) and four-digit numbers are grouped: `2 000`, `12 000`, `1 250,5`, `1 250 000`.
- **Money**: `120 €` and `1 250,5 €` through the app's own `AppCurrency.format` (narrow presentation, which EUR takes); the locale's own full form is `120,00 €`. The euro sign follows the amount after U+00A0 and never precedes it. Compact amounts are the engineering flag in `## Identity`, not a copy rule.
- **Percent is post-positioned and separated by a no-break space**: `40 %`, `100 %`. Both ICU (`.percent` for `sk_SK`) and Microsoft §4.1.17 ("Symbols like the percent sign are post-positioned and separated by a nonbreaking space") say so. `en`'s glued `56%` is an imported shape; `-%lld%%` becomes `-%lld %%`.
- **No-break space also follows one-letter prepositions and conjunctions** (`v`, `s`, `k`, `a`, `o`, `z`, `u`, `i`) — Microsoft §4.1.17, and visible throughout Apple's Slovak: "Keď apke „%@“ poskytnete prístup k času pred obrazovkou … a limity pre apky a webstránky." Translators type a normal space; the coordinator normalises before integration and the catalog comment records it.
- **Dates**: numeric `31. 12. 2026` with U+202F (narrow no-break space) after each period; wide `31. decembra 2026` with the month in the **genitive**; weekday `utorok`, weekday plus date `utorok 12. 5.`. Ordinals written with numerals take a period (Microsoft §4.1.14, "v 3. odseku"), which is why the date components carry one.
- **Time is 24-hour**: `9:41`, `23:59`. No AM/PM exists.
- **Quotation marks are „ “** (U+201E opening, U+201C closing), with ‚ ' (U+201A, U+2018) nested inside. Straight `"` is never correct — Microsoft §4.1.14: "In Slovak language we NEVER use English quotation marks". The same section bans quoting UI items and product names for emphasis, so `component.errorView.message` and the other three "Try Again" keys read "Klepnite na tlačidlo Skúste znovu" rather than quoting the button — `tlačidlo` (button) is the case-carrier the finite imperative label cannot supply itself, per `## Audience and register`; the **exception** is a string that mirrors an iOS alert, where Apple's own punctuation wins verbatim (Apple quotes the app name in the Screen Time message, „%@“, and does **not** quote it in the notification title). `moneyfesting.details.quoteWrapper` `"%@"` and `notifications.contentExtension.quoteDecoration` become `„%@“` — real quotations, which is exactly what §4.1.14 keeps the marks for.
- **Dashes**: en dash (U+2013) with spaces for ranges and for an isolated aside (Microsoft §4.1.14; the em dash is not used in Slovak). `en`'s two em-dash keys (`achievements.streak.comebackBody`, `share.alert.savedToPhotosMessage`) take a spaced en dash; `en`'s five spaced-hyphen attribution keys (`quote.display.attribution`, `widgets.quotes.authorDecoration` and siblings) take "– %@".
- **Ellipsis: three periods**, never U+2026 — Microsoft §4.1.14, "Three periods have to be used, any other number is defective". This agrees with the `en` catalog majority (9 keys with three periods against 2 with the character).
- **Multiplication** stays `×` (5 `en` keys, `achievements.category.wages.description` among them).
- **Plural categories: one · few · other are required; `many` is reachable only from fractions.** ICU 76.1.0.0 (CLDR 46.0.0.0) for `sk`: of the integers 0–999999, `one` takes exactly 1, `few` takes 2, 3 and 4, and `other` takes all 999996 others including 0; `many` is selected by 0.5, 1.5 and 2.5 and by no integer at all, including 10⁶ and above. Xcode 26.1 still lists `many` (`XCStringsParser.framework/.../variationConfigFile.plist -> PluralRule.ComplementedPluralKeys.sk`), so the catalog asks for it; an `%lld` count never reaches it, and a compiled-catalog runtime check over 0, 1, 2, 3, 5, 12, 20, 22, 100, 101, 10⁶, 10⁶+1 and 2·10⁶ never picked it.
- **Boundary integers to exercise on every plural key**: 1 (`one`), 2 and 4 (`few`), 0 and 5 (`other`), 12 (`other`, and the surprise against 2), 21 and 22 (`other`, unlike Russian), 101 and 102 (`other`, the surprise against 1 and 2), plus the fractions 0.5 and 1.5 if any surface ever formats a decimal count. The two that catch a wrong table first are **2 vs 12** and **2 vs 102**.
- **How numerals attach to nouns** — four forms, one per category, all read off Apple's Slovak runtime (`CoreServices/SpringBoard.app | SpringBoardPlurals.stringsdict | DATA_PLAN_ADD_EXPIRATION_BODY_DAYS/hours`; `CoreServices/VoiceOverTouch.app | VOTLocalizedStrings.stringsdict | hours.format/hours` and `hours.minutes.format/minutes`):

| category | integers | *deň* | *minúta* | *hodina* | grammar |
|---|---|---|---|---|---|
| one | 1 | %lld deň | %lld minúta | %lld hodina | nominative singular |
| few | 2, 3, 4 | %lld dni | %lld minúty | %lld hodiny | nominative plural |
| other | 0, 5 and everything else | %lld dní | %lld minút | %lld hodín | genitive plural |
| many | fractions only | %lld dňa | %lld minúty | %lld hodiny | genitive singular, the form a decimal takes (1,5 dňa) |

  The counted noun changes case, so a plural key can never be built by concatenating a number with a fixed noun; every count lives in one key with its own variations. The 6 keys that carry plural variations in `ro` while `en` has a single `stringUnit` (`achievements.streak.body`, `.comebackBody`, `.headline`, `.milestoneBody`, `.nextMilestoneBody`, `.weekAccessibility`) need the same one/few/other split in Slovak, plus the 29 keys that already have `en` variations.
- Direction is left to right; nothing in `references/agent-protocol.md`'s RTL rules applies.

## Length trigger

- **A Slovak string longer than 1.25× its `en` length goes on the render list.** The ratio is measured from Apple's own Slovak translations, not guessed: across 45 957 unique English/Slovak pairs from the iOS 26.1 (23B86) runtime (78 770 pairs before deduplication, accessibility bundles excluded), the median Slovak string is 1.125× its English source, p75 is 1.333× and p90 is 1.588×. 1.25 is the ratio, rounded to 0.05, that Slovak exceeds as often (29.2%) as Apple's Romanian exceeds 1.35× (31.6%) — the statistic closest to the Romanian catalog's own 299 of 1135. A flat 1.35× would flag only 20.0% of Slovak and let real overflows through.
- Short strings expand hardest, which is exactly where the app's controls and captions live: 1–10 character sources have a median of 1.25× and a p90 of 2.0×, while 41–120 character sources sit at 1.082× median. The all-caps subset (922 pairs) is worse again at the short end: p75 1.6×, p90 2.5× for 1–10 characters, so the uppercase eyebrows and stat captions (`insights.summary.*`, `widgets.focusRing.title`, `.row.money`, `.row.streak`, `onboarding.hourlyWage.unit`) are the first render checks.
- **There is no share of the catalog to report**: 0 Slovak units exist at snapshot 2026-09-16, so the only distribution available is Apple's. Once the first batch ships, replace this bullet with the catalog's own count over 1.25×.
- Counts never establish fit. Verdicts come from render evidence against each view's own floor and Dynamic Type cap (`references/surface-budgets.md`, `references/render-evidence.md`). Shortening cuts words, never facts; a fact that must go moves to a neighbouring element and the key's comment says so. Accessibility strings are exempt.

- Preserve every source emoji, add none. Flag an off-voice source line rather than matching Apple's exuberance.

## Decided conflicts

| Conflict | Winner | Rule |
|---|---|---|
| Button form: Romanian's bare imperative (the model brief) against the Slovak infinitive | **infinitive** (Zrušiť, Uložiť, Pokračovať) | a decision in another locale is not evidence in this one; Microsoft's Slovak guide §5.5.2 states the infinitive rule and every generic iOS control in `UIKitCore` Slovak is an infinitive |
| Gender: Microsoft §3.1 asks for both forms, "use Vytvoril/-a", and "always try to create feminine+masculine versions" | **the project rule**: no slash forms, no doubled endings (`references/locale-decisions.md` `## Voice choices that need locale review`, `## Gender in UI copy`) | the project rule is narrower and the `vy` plural participle makes the slash unnecessary; a "/-a" ending in a Slovak candidate is a finding |
| "Try Again": Apple's SpringBoard Slovak is the plural imperative "Skúste znovu" while the generic Retry control is the infinitive "Zopakovať" | **both, split by role** | a bare button takes the infinitive; a label quoted inside a sentence, and the four "Try Again" keys, take the imperative, because that is the string the user sees on that device alert. Apple's own catalog is not uniform on "Try Again" (GameCenter extensions render it as the infinitive "Skúsiť znovu"/"Skúsiť to znovu"), so the split rests on register — a system alert vs. an in-app control — not on Apple being consistent |
| Don't Allow: "Nepovoliť" (UIKit, UserNotifications) against "Nepovoľovať" (FamilyControls) | **per-alert mirror** | the mock reproduces one specific iOS alert; the Screen Time mock takes "Nepovoľovať", the notification mock "Nepovoliť" |

| Focus term against the iOS Focus mode | **no conflict in Slovak** | iOS Slovak calls the system Focus mode "Môj čas", not a focus word, so "sústredenie" is free; Romanian's `focus_session` overlap argument does not transfer |
| Add Widget on the edit menu against the gallery button | **one form, "Pridať widget"** | Apple's two Slovak values differ only by a layout space, so the single shared key is correct and no new key is needed |

## Open decisions

Each item is mirrored in `glossary/sk.json` `open` with `id`, `options`, `recommended`, `recommended_reason`, `decided_by: "user"`, `status: "open"` and a note carrying the keys, the rule and the meanwhile. Nothing is `translated` in Slovak yet, so "keys stay locked" does not apply; the meanwhile rule is what a new string does.

- **`address_formality` — `vy` or `ty`.** Affected: every reader-directed string, roughly 600 of 1189 keys, and the whole of `## Address and gender`. Rule: the locale brief sets the address; app-owned copy keeps it and only iOS mirrors follow the device. Options: **`vy`** — Apple's Slovak addresses a single iPhone owner with `vy` in every system string the app sits beside (notification alert, Screen Time alert, Health sheet), Microsoft's guide writes its examples in `vy` while asking for a conversational tone, and the plural *l*-participle is gender-neutral, so the app's 40-plus reader-directed past-tense lines need no gender strategy at all; **`ty`** — matches `en` and the shipped `ro`, reads younger, and suits a coach voice, but forces a gendered singular participle on every "You showed up", "you're back", "You focused" line, which Apple's own `ty` variants dodge only by rewriting into the impersonal "podarilo sa ti". Recommended: **`vy`**, because it is the register a Slovak reader meets in the iOS screens this app mocks and it removes the gender problem instead of managing it. Meanwhile: agents write `vy`, the mock alerts take Apple's `vy` either way, and the adjudicator lists every key whose reading would change under `ty`.
- **`focus_session` — what the app's central concept is called.** Affected: `moneyfesting.details.*`, `focusTask.*`, `widgets.startFocus.*`, `profile.sessionDetails.*`, `insights.focus.*`, `onboarding.welcome.preview.*`, plus the `widgets.streak.*` lines that mention it — about 120 keys. Rule: one preferred term per concept, aligned catalog-wide, never chosen per string. Options: **"sústredenie"** — Apple's own Slovak for concentrating ("Ťažkosti so sústredením", `HealthUI.framework | HealthUI-Localizable-Chamomile.strings | PHQ9_QUESTION_7`; "keď sa potrebujete sústrediť", `AccessibilityAppIntents.appex | Localizable.strings | BACKGROUND_SOUNDS_DESCRIPTION`), an everyday word a reader without English understands, and free of any clash with the iOS Focus mode, which Slovak calls "Môj čas"; **"relácia sústredenia"** — matches Apple's "relácia" for a session (`AirDropUI.app | Localizable.strings | End Session` "Ukončiť reláciu"), but "relácia" reads as a computing session or a broadcast and is heavy for a timer screen; **"fokus"** — short and current in Slovak startup speech, but an English loan the plain-language rule argues against. Recommended: **"sústredenie"**, one word, Apple's own vocabulary, and no collision with anything on the device. Meanwhile: agents write "sústredenie" and the adjudicator lists every key that touched the term, so a flip is one follow-up batch rather than a per-string argument.
- **`badge_term` — "odznak" or "ocenenie" for an achievement badge.** Affected: the 24 `achievements.badge.*.name` keys, `achievements.badgeUnlock.title`, `achievements.gallery.*`, `achievements.card.*`, `paywall.benefit.*` — about 70 keys. Rule: use Apple's term where the app names the same object Apple names. Options: **"odznak"** — the literal badge, which supports the workplace conceit (an employee badge you are given for showing up) and reads naturally in a gamified app, but is the same word Apple uses for notification icon badges ("odznaky ikon") inside the notification mock the app already ships, so the two senses would meet on one onboarding screen; **"ocenenie"** — Apple's own word for a Fitness achievement ("Toto ocenenie získate…", `FitnessUIAssets.bundle | Localizable.stringsdict | ACHIEVEMENT_UNACHIEVED_DESCRIPTION`), unambiguous, but it means *award* and pulls against the payroll metaphor. Recommended: **"odznak"**, because the conceit is the product (Hired, Salaried, Clocked in, Tenure) and a Slovak reader separates a notification badge from an achievement badge by context on two screens that never share a view. Meanwhile: agents write "odznak", never use "odznak" inside the notification mock (which mirrors Apple's "odznaky ikon" verbatim), and the adjudicator lists both screens.
- **`app_noun` — "apka" or "aplikácia".** Affected: the 18 `en` keys naming an app generically and every sentence that names Moneyfesting after a noun (`insights.mood.permissionMessage`, `share.alert.photoAccessDeniedMessage`, `widgets.startFocus.openApp`, `screenTime.*`). Rule: app-owned copy names things the way the device does. Options: **"apka"** — Apple's Slovak default, including inside the Screen Time alert this app mocks ("Keď apke „%@“ poskytnete prístup") and the App Limits row ("Limity pre apky"), short, and the register the reader already sees; **"aplikácia"** — the formal word, which Apple itself uses in the Photos add-only alert ("Aplikácia „%@“ chce pridať položky…"), so it is not wrong, only heavier and longer in a locale that already expands 1.25×. Recommended: **"apka"**, because it is what the device says on the very screens the app reproduces, and because it is shorter where width is tight. Meanwhile: agents write "apka" in app-owned copy and copy Apple's own noun verbatim inside any mocked alert, even when the two differ on the same screen.
- **`restore_button` — what `paywall.button.restore` says.** Affected: `paywall.button.restore` (en "Restore"; its comment says the button restores a subscription bought previously). Rule: app-owned copy keeps this brief's address and defaults to Apple's wording for a matching control. Apple has no "Restore Purchases" label on disk; StoreKit's SwiftUI views say "Obnoviť odber" and "Obnoviť chýbajúce nákupy" (`_StoreKit_SwiftUI.framework | Localizable.strings | RESTORE_SUBSCRIPTION_LABEL, RESTORE_PURCHASES_LABEL`). Options: **"Obnoviť odber"** — Apple's own label for exactly this action, and "odber" is Apple's Slovak for a subscription throughout the Apple Account and App Store screens; **"Obnoviť predplatné"** — the everyday Slovak word for a subscription, which most Slovak readers use, at the cost of naming the App Store object differently from the App Store; **"Obnoviť nákupy"** — closest to the English source but names purchases the paywall does not sell. Recommended: **"Obnoviť odber"**, because the button reaches into the App Store and should use the App Store's own Slovak noun. Meanwhile: agents write "Obnoviť odber", and any other paywall line that needs the noun uses "odber" too, so the screen does not carry two words for one thing. A yes needs a paywall render check, since the label is a secondary link under the primary button.
