## Romanian provenance

Where the guide and the shipped catalog differ, the catalog majority at `c8a49dd` is the stronger evidence, because the owner accepted it; the guide's Cancel = Renunță lost to the shipped Anulează that way, and "sesiune de focus" stays an open owner decision. ## Hebrew register research (2026-09-16)

The `he` brief's first pass (commit `7c2dab3`) took every register and gender-strategy rule from iOS's own Hebrew chrome, because that is the harvest procedure below run for every locale. iOS chrome is accurate for anything the app mirrors verbatim (Platform terms), but it is system-settings copy, not evidence for how a warm consumer app should sound — Apple's own impersonal forms (`ניתן ל־`, `יש ל־`) read closer to an instruction manual than to a product's voice. A second pass added two evidence tiers the harvest below does not produce: real Israeli UX-writing practice, and a live competitor cross-reference under `references/locale-decisions.md` `## Platform terms`'s "Cross-reference the same concepts against real competitors" procedure, run here for the first time in the version-1 set (no other locale brief has populated `TEMPLATE.md`'s optional comparable-apps table yet).

| Question | Source | Grounds |
|---|---|---|
| How does a professional Israeli UX writer keep gender-neutral Hebrew from sounding formal or robotic? | Kinneret Yifrah, studio Nemala, leads Israel's UX-writing/microcopy community and wrote [`מיקרו-קופי: המדריך המלא`](https://www.microcopy.co.il/microcopy-book) ("Microcopy: The Complete Guide", published Hebrew, English and Korean) | [Fireside chat: Gender-neutral writing in UX with Kinneret Yifrah](https://www.localizationstation.com/posts/gender-neutral-writing-in-ux-with-kinneret-yifrah), fetched 2026-09-16: she describes overturning an edit that swapped a casual word for a more formal one, and names plural address and verbal-noun/infinitive forms as gender-free tools that stay casual |
| What has this scaled to beyond one writer's opinion? | Yifrah and Liron Libskind Mulyan co-authored the voice-and-tone guidelines for Israel's government digital products, with a dedicated gender-inclusive-writing chapter, now adopted across thousands of products | same fireside chat |
| What are the concrete techniques, with Hebrew examples? | Nemala's own published guide | [`כתיבה שוויונית: מדריכים, פתרונות ומקורות`](https://www.microcopy.co.il/how-to-write-for-all-genders) ("Equitable writing: guides, solutions and sources"), fetched 2026-09-16: verbal nouns (`הרשמה`, `כניסה`, `שמירה`), infinitives (`להוסיף לסל`, `להאט`), words spelled the same for both genders (`ממך`, `רוצה`, `נרשמת`), first-person reframing (`אני רוצה להירשם`) and paired doubling (`ברוכים הבאים והבאות`) for what nothing shorter covers; slash notation (`משתמש/ת`) is listed but de-emphasised against all of the above |
| What do real Hebrew-shipping competitors in Moneyfesting's own category actually write? | iTunes Search API, `country=il`, checked against each result's `languageCodesISO2A` and confirmed live at `https://apps.apple.com/il/app/id<id>?l=he` (an English-fallback listing is not evidence) | three genuine `il`-storefront habit trackers, cited with app, id and fetch date in `he.md` `## Audience and register`; no manifestation, affirmation or money-mindset app returns a genuine Hebrew listing on `il` at this snapshot, itself recorded there as a finding rather than left silent |

### Full-catalog translation and its verification (2026-09-16)

The owner's delegation extended from the pilot batch to the remaining ~1150 keys (all 64 worklist batches) and the full shield set (25 pairs), through the same translator/blind-editor protocol, then a dedicated claim-accuracy pass: blind back-translation of the highest-stakes content (paywall, permission mirrors, streak/savings money claims, shield tone, 147 ids) followed by a coordinator disposition. That pass returned 7 flagged items; cross-checking each against this brief's own `## Platform terms` harvest (not given to the blind or compare agents) resolved 3 as false positives and left 2 real, now-fixed defects plus one non-actionable note:

- **False positives, verbatim-correct as shipped:** `onboarding.notificationPermission.alertAllow`/`.alertDoNotAllow` (`אישור`/`סירוב`) and `onboarding.screenTimePermission.alertMessage`'s `או` connector all match this brief's harvested Apple wording (`## Platform terms`) exactly; the verification pass assumed the two permission alerts should use identical Hebrew for "Don't Allow" when Apple's own iOS genuinely uses two different words for the two alerts (`he.md` Control forms, "Don't allow" row) — a lesson for any future verification pass run without the full brief in context.
- **Fixed:** `paywall.button.startTrial` was missing "free" (`חינם`), inconsistent with sibling trial strings (`paywall.trialToggle`, `.trialPitch`); now `התחלת תקופת ניסיון חינם`. `paywall.onboardingSubscription.legalText`'s "unless [it] is canceled" used a passive feminine verb that grammatically agreed with "the trial period" rather than naming what must be canceled; now states the object explicitly, `אלא אם המינוי בוטל קודם לכן`.
- **Noted, not fixed:** `onboarding.screenTimePermission.message` (app-owned, not a verbatim mirror) uses the feminine pronoun for the app-name placeholder while the verbatim-mirrored `alertMessage` uses Apple's masculine one for the same referent; the mismatch is real but each string is independently correct for its own rule (one must match Apple, one is free to be grammatically correct on its own), so no change was made.

Also fixed in this pass, in the skill's own scripts rather than in Hebrew copy: `scripts/catalog_check.py`'s C1 check previously accepted a dropped plural placeholder only in the `zero`/`one` categories; Hebrew's `two` (dual, e.g. `יומיים`) is equally an exact-count category and needed the same allowance. Its shield parser (`SHIELD_INIT`) was a fixed six-field positional regex that silently returned zero entries once `ShieldMessage` gained per-locale optional fields (`titleHebrew`/`bodyHebrew`); replaced with the same field-name-based parser (`shield_fields`) `worklist.py` and `term_audit.py` already used, which tolerates any future locale field without a script change, and extended `SHIELD_TARGET_FIELD` with `"he": "Hebrew"` so `worklist.py`'s own shield completeness check recognizes Hebrew shield pairs as done.

This does not overturn `he.md` `## Open decisions` `gender_strategy`, but it changes what the recommendation rests on: option (1) is now backed by the named professional standard for Israeli product writing, not only by OS-chrome mirroring, and that same source's caution — that defaulting to the impersonal frame instead of the warmer verbal-noun, infinitive and unpointed-past forms is what makes gender-neutral Hebrew read bureaucratic — is folded into `he.md` `## Address and gender`'s reach-order. The competitor check cuts the other way on one point: two of the three genuine competitors ship masculine-singular by default, which is real, current evidence for option (2), not an assumption; the third ships informal plural (`אתכם`), a working gender-free register neither iOS nor this brief had previously named, now `he.md` strategy 7. A native Hebrew UX-writing review remains the recommended check before the owner closes `gender_strategy` (`he.md` Identity).

## Locale research (2026-09-16)

The briefs for the decided target set were written from first-party evidence gathered in one pass; `references/locale-decisions.md` `## Platform terms` carries the reproducible procedure.

| Question | Method | Grounds |
|---|---|---|
| What does Apple call this in the target language? | decode every `en`/`Base`/`en_GB` `.strings` and `.stringsdict` in the iOS 26.1 (23B86) simulator runtime, find the key by its English value, read the same key in the locale's `lproj` | each brief's Platform terms rows and the system-mirror values, cited as `bundle \| table \| key` |
| Which plural categories does the locale really select? | ICU `uplrules_open`/`uplrules_select` over every integer below a million plus fractions, cross-checked with Xcode's own `PluralRule.ComplementedPluralKeys` table | `scripts/catalog_check.py` `PLURAL_REQUIRED` and `PLURAL_OPTIONAL`, and each brief's boundary values |
| How do numbers, money, dates and quotes render? | Foundation with the app's own `AppCurrency.format`/`formatCompact` replicated verbatim, invisible characters recorded as code points | the Numbers section of each brief and the compact-suffix engineering finding |
| Which tag does a device actually receive? | `Bundle.preferredLocalizations(from:forPreferences:)` against the runtime's real `lproj` lists and against candidate app tag sets | the catalog tag in each brief's Identity, and the `nb`/`no`, `he`/`iw`, `es-MX`/`es-419` and `pt-BR`/`pt` decisions |
| How much does the language expand? | ratio distribution of Apple's own translations against their English source, calibrated so the procedure returns `ro`'s shipped 1.35x | the length trigger in each brief, display-width based for `ja` and `ko` |
| Can the store list this language? | App Store Connect's published localization list, fetched 2026-09-16 | the store rows in each brief and the Icelandic and Bulgarian gaps |

Every row in a brief outside `ro` is agent research: no shipped copy, no native source, and no owner acceptance. Glossary rows carry `decided_by: "skill-seed-2026-09-16"` so an owner can tell research from accepted copy, and `scripts/brief_check.py` fails a brief that claims human approval. Two independent checks ran over each locale: a language specialist trying to refute the choices, and the script for structure, schema, cited keys and evidence.

## Primary references for maintenance

- [Apple localization](https://developer.apple.com/localization/) and [Code-along: Explore localization with Xcode](https://developer.apple.com/videos/play/wwdc2025/225/): catalog workflow, translator context and platform surfaces. Keep repository conventions where they intentionally differ from generic examples.
- [Apple StoreKit displayPrice](https://developer.apple.com/documentation/storekit/product/displayprice): preserve runtime-localized purchase prices once the app uses them; today it has none (`references/project-context.md` Subscription row).
- [Unicode CLDR plural rules](https://www.unicode.org/cldr/charts/latest/supplemental/language_plural_rules.html): target-specific plural categories; verify against the shipping runtime, since Romanian adds a `few` category that English lacks.
- [Microsoft locale guides](https://learn.microsoft.com/en-us/globalization/reference/microsoft-style-guides): language and region conventions, including Arabic, Hebrew and regional Portuguese and Spanish, used alongside Moneyfesting's own voice card, never instead of it.
- [MQM error typology](https://www.themqm.org/mqm-pillars/typology/): separate accuracy, linguistic, style, audience or locale and presentation findings. The acceptance criteria in `references/agent-protocol.md` "Acceptance and evidence" are Moneyfesting-specific, not MQM certification.
- [Smartling transcreation](https://help.smartling.com/hc/en-us/articles/4641758074523-What-is-Transcreation): intent and tone adaptation with creative alternatives; it does not demonstrate conversion lift for this app.
- [Experts, Errors, and Context](https://aclanthology.org/2021.tacl-1.87/): contextual professional evaluation, the reason every packet carries screen, state and neighbours.
- [Rethinking Round-Trip Translation for Machine Translation Evaluation](https://aclanthology.org/2023.findings-acl.22/): round-trip evaluation compares propositions, not surface forms, which is why a back-translation of "plouă cu găleata" reading "it's pouring" passes and a changed amount, negation or condition fails.

## Maintenance notes

- Paths: every checkout path cited in `references/*.md` is a snapshot. Run `scripts/check_paths.sh --app-root <checkout>` after the app repo moves files (commit `057a80d` moved the widget copy files once already) and before publishing a skill change; a missing path is a skill defect, not an app defect.
- Facts: counts and line numbers carry "snapshot 2026-09-15". Refresh them from `scripts/catalog_check.py` output and a fresh grep rather than editing numbers by hand; `references/project-context.md` "Catalog state" and "Enabling a locale" list what to re-verify.
- Pilot regression: after any change to SKILL.md, a locale brief, `references/voice-card.md` or the control-form entries of a glossary, run the pilot batch (`scripts/worklist.py --pilot`) alone through every stage before fan-out, per `references/agent-protocol.md` "Tiers, order and batches"; treat its findings as corrections to the brief and glossary and list them by category in the report.
- Evals: `evals/evals.json` holds the regression cases with fixtures under `evals/files/`; add a case whenever a run surfaces a failure class the protocol did not catch, and keep each case's expectation phrased in the report template's terms so runs stay comparable.
- Scripts: Python 3 standard library only, every script prints `--help`, and none writes into the app checkout except `scripts/catalog_apply.py` on an explicit path; keep that contract when adding a script.
- Workflow controls (fresh target-only agents, the leak check, bounded revision rounds, version-linked evidence, a final adjudicator) are proposed mechanisms: test their behaviour on the pilot and disclose any stage that did not run in the report's Reviews line.
